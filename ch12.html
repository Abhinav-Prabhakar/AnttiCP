12.1

Strong Connectivity

A directed graph is strongly connected when every node can reach every other node.

A directed graph can always be divided into strongly connected components. Each component contains a maximal set of nodes with a path from any node to all the others, and the components form an acyclic component graph that captures the deep structure of the original graph.

Contract, then sort

A component graph is a directed acyclic graph, so it is easier to process than the original. With no cycles, we can always construct a topological sort and use dynamic programming on it. The deep structure of a directed graph is the structure of its components, not its edges.

  • A = {1, 2}
  • B = {3, 6, 7}
  • C = {4}
  • D = {5}
A→ B→ C→ D

Also B → D. The topological order is A, B, C, D — or A, B, D, C.

12.1.1

Kosaraju’s Algorithm

Kosaraju’s algorithm finds the strongly connected components of a graph efficiently. It performs two depth-first searches: the first constructs a list of nodes according to the structure of the graph, and the second forms the strongly connected components.

Why the reversed order works

After this, the algorithm goes through the list created by the first search, in reverse order. If a node does not belong to a component, the algorithm starts a depth-first search that adds all new nodes it finds to a new component. Since all edges are reversed, the components do not “leak” to other parts of the graph.

The time complexity is O(n + m), because the algorithm performs two depth-first searches.

12.1.2

The 2SAT Problem

In the 2SAT problem we are given a formula

(a1 ∨ b1) ∧ (a2 ∨ b2) ∧ ⋯ ∧ (am ∨ bm),

where each ai and bi is either a logical variable (x1, x2, …, xn) or its negation (¬x1, ¬x2, …, ¬xn). Our task is to assign each variable a value so that the formula is true, or state that this is not possible. An instance can be represented as an implication graph whose nodes are the variables xi and their negations ¬xi, with edges giving the connections between them. Each pair (ai ∨ bi) generates two edges: ¬ai → bi and ¬bi → ai. The structure of this graph tells us whether the variables can be assigned values that make the formula true. That is possible exactly when no node xi and its negation ¬xi belong to the same strongly connected component.

One formula, two verdicts

satisfiable

The literals of every variable lie in different components, so an assignment exists.

x1 = falsex2 = falsex3 = truex4 = true

If a solution exists, the values for the variables can be found by going through the nodes of the component graph in a reverse topological sort order. At each step, we process a component that does not contain edges that lead to an unprocessed component. When constructing the solution, we first process the component D where x4 becomes true. After this, we process the component C where x1 and x2 become false and x3 becomes true. All variables have been assigned values, so the remaining components A and B do not change the values of the variables.

Why 3SAT is different

A more difficult problem is 3SAT, where each part of the formula is of the form (a ∨ b ∨ c). It is NP-hard, so no efficient algorithm is known. The jump from two to three literals is a genuine change of difficulty, not an implementation detail.

12.2

Complete Paths

An Eulerian path uses every edge once. A Hamiltonian path visits every node once.

In this section we discuss two special types of paths: an Eulerian path goes through each edge exactly once, and a Hamiltonian path visits each node exactly once. They look similar at first glance, but the computational problems are very different.

12.2.1

Eulerian Paths

An Eulerian path goes exactly once through each edge of a graph. If it starts and ends at the same node, it is called an Eulerian circuit. Whether these paths exist depends on the degrees of the nodes.

The degree test

An undirected graph has an Eulerian path exactly when all the edges belong to the same connected component and

  • 1the degree of each node is even, or
  • 2exactly two nodes have odd degree, and all other nodes have even degree.

In the first case every Eulerian path is also a circuit. In the second, the odd-degree nodes are the endpoints of a path that is not a circuit.

For a directed graph we look at indegrees and outdegrees. It contains an Eulerian path exactly when all the edges belong to the same strongly connected component and either every node has equal indegree and outdegree, or one node has indegree one larger than its outdegree, another has outdegree one larger than its indegree, and all the rest are equal.

In the trail graph, nodes 1, 3, and 4 have degree 2, and nodes 2 and 5 have degree 3. Exactly two nodes are odd, so an Eulerian path runs between 2 and 5, but there is no Eulerian circuit. The walk 2 → 1 → 4 → 5 → 3 → 2 → 5 uses all six edges.

Constructing the path: Hierholzer’s algorithm

The algorithm begins with an empty circuit containing a single node and extends it step by step by adding subcircuits. It continues until all edges are in the circuit. To extend it, find a node x in the circuit that has an outgoing edge not yet included. Then construct a new path from x using only edges outside the circuit. Sooner or later the path returns to x, creating a subcircuit. Every edge is used once, so the construction is O(n + m).

If a graph has an Eulerian path but no circuit, Hierholzer’s algorithm still finds the path: add an extra edge, build the circuit, then remove the edge. In an undirected graph, add it between the two odd-degree nodes.

12.2.2

Hamiltonian Paths

A Hamiltonian path visits each node of a graph exactly once. If it begins and ends at the same node, it is a Hamiltonian circuit. Problems related to Hamiltonian paths are NP-hard: nobody knows an efficient general way to check whether one exists.

A simple way to search for a Hamiltonian path is backtracking through all possible ways to construct one. Its time complexity is at least O(n!), because there are n! orders for n nodes. Dynamic programming gives a more efficient O(2nn2) solution: for each subset of nodes S and each node x ∈ S, determine whether there is a path that visits every node of S once and ends at x. That is a real improvement, but still exponential — and the gap grows fast.

A useful special case

Of course, in some special cases we can be certain. For example, a complete graph — an edge between every pair of nodes — surely contains a Hamiltonian path. More generally, sufficient conditions can be checked cheaply even though the general problem cannot.

12.2.3

Applications

A De Bruijn sequence corresponds to an Eulerian path in a graph where each node is a string of n − 1 characters and each edge adds one character. A knight’s tour corresponds to a Hamiltonian path in a graph whose nodes are board squares, with an edge wherever a knight can move between them.

12.3

Maximum Flows

Send as much flow as possible from a source to a sink, without exceeding any edge’s capacity.

In the maximum flow problem we are given a directed weighted graph with two special nodes: a source, with no incoming edges, and a sink, with no outgoing edges. Our task is to send as much flow as possible from source to sink. Each edge has a capacity limiting the flow through it, and at every intermediate node the incoming and outgoing flow must be equal.

It turns out that the maximum flow problem is connected to another graph problem, the minimum cut problem, where our task is to remove a set of edges from the graph such that there will be no path from the source to the sink after the removal and the total weight of the removed edges is minimum. It is not a coincidence that the maximum flow and minimum cut are equal in our example graph. Rather, it turns out that they are always equal, so the concepts are two sides of the same coin.

12.3.1

The Ford–Fulkerson Algorithm

The Ford–Fulkerson algorithm finds the maximum flow. It begins with an empty flow and at each step finds a path from source to sink that generates more flow. When no such path remains, the maximum flow has been found.

The Ford–Fulkerson algorithm does not specify how to choose the paths that increase the flow. It will terminate sooner or later and correctly find the maximum flow, but its efficiency depends on those choices. A simple way to find paths is depth-first search. Usually this works well, but in the worst case each path increases the flow by one unit, and the algorithm is slow. The Edmonds–Karp algorithm chooses the path with as few edges as possible, by using breadth-first search. It can be proved that this makes the flow increase quickly, and the time complexity is O(m2n). The capacity scaling algorithm uses depth-first search to find paths where every edge weight is at least an integer threshold. Initially the threshold is some large number, for example the sum of all edge weights. Whenever a path cannot be found, the threshold is divided by 2, and the algorithm stops when it becomes 0. Its time complexity is O(m2 log c), where c is the initial threshold.

Reading the minimum cut from the final residual graph

Once the Ford–Fulkerson algorithm has found a maximum flow, it has also determined a minimum cut. Let A be the set of nodes reachable from the source using positive-weight edges. The minimum cut consists of the original edges that start in A, end outside A, and are fully used in the maximum flow.

In the example the reachable set is {1, 2, 3}. The cut edges are 2 → 4, 3 → 4, and 3 → 5, with capacities 3 + 2 + 2 = 7.

12.3.2

Disjoint Paths

Many graph problems can be solved by reducing them to maximum flow. Our first example: given a directed graph with a source and a sink, find the maximum number of disjoint paths from the source to the sink.

This problem reduces to maximum flow as well. Since each node can appear in at most one path, we must limit the flow through nodes. The standard construction divides each node into two: the first takes the incoming edges, the second the outgoing edges, with a new edge from the first to the second. The maximum flow in the resulting graph equals the maximum number of node-disjoint paths.

Recovering the paths

After the maximum flow is constructed, the paths can be found greedily by following them from source to sink, removing used edges and repeating. The flow value guarantees that the greedy set has the same size as the maximum.

12.3.3

Maximum Matchings

A maximum matching is a maximum-size set of node pairs, each joined by an edge and each node in at most one pair. In a general graph this requires tricky algorithms, but if the graph is bipartite the problem is much easier. In that case we can reduce it to maximum flow.

Reduce, then match

We reduce bipartite maximum matching to maximum flow by adding a source and a sink, with edges from the source to each left node and from each right node to the sink. The maximum flow in the resulting graph then equals the maximum matching in the original.

Hall’s theorem tells us whether a bipartite graph has a matching that contains all left or right nodes. Suppose we want all left nodes matched. Let X be any set of left nodes and f(X) the set of their neighbors. By Hall’s theorem, such a matching exists exactly when |X| ≤ |f(X)| for every possible set X.

Then, let X = {2, 4} which yields f(X) = {7}. In this case, |X| = 2 and |f(X)| = 1, so the condition of Hall’s theorem does not hold. This means that it is not possible to form a perfect matching for the graph. This result is not surprising, because we already know that the maximum matching of the graph is 3 and not 4.

A minimum node cover is a minimum set of nodes such that every edge has at least one endpoint in it. In a bipartite graph, König’s theorem says its size always equals the size of a maximum matching. The nodes outside a minimum node cover form a maximum independent set.

12.3.4

Path Covers

A path cover is a set of paths such that every node of the graph belongs to at least one. In a directed acyclic graph, finding a minimum path cover reduces to finding a maximum flow in another graph.

Node-disjoint covers

In a node-disjoint path cover, each node belongs to exactly one path. To find a minimum one, build a matching graph with a left and a right node for each original node. Add an edge from a left node to a right node whenever the original graph has that edge, plus a source joined to all left nodes and a sink joined from all right nodes. Each edge in the maximum matching then corresponds to an edge in the minimum node-disjoint path cover.

minimum cover = n − c = 7 − 4 = 3

A general path cover allows a node to belong to more than one path. It may be smaller than a node-disjoint cover, because a node can be used multiple times. In this graph the minimum general cover has two paths. It is found almost like a node-disjoint cover: add edges to the matching graph so that a → b exists whenever there is a path from a to b in the original graph, possibly through several nodes.

An antichain is a set of nodes in a graph such that there is no path from any node to another node using the edges of the graph. Dilworth’s theorem states that in a directed acyclic graph, the size of a minimum general path cover equals the size of a maximum antichain. In this graph, nodes 3 and 7 form an antichain of two nodes. This is a maximum antichain, because a minimum general path cover of this graph has two paths.

12.4

Depth-First Search Trees

Depth-first search does not only visit a graph. It leaves a tree behind, and the edges outside that tree explain the graph’s cycles.

When depth-first search processes a connected graph, it creates a rooted directed spanning tree: a depth-first search tree. The edges can then be classified by their role during the search. In an undirected graph there are two types: tree edges that belong to the tree and back edges that point to already visited nodes. A back edge always points to an ancestor.

Every node stores the smallest discovery time reachable from its subtree. Back edges pull that value upward.

The rules

A tree edge a → b is a bridge when low(b) > disc(a).

12.4.1

Biconnectivity

A connected graph is biconnected if it remains connected after removing any single node and its edges. A node is an articulation point if removing it disconnects the graph. Similarly, an edge is a bridge if removing it disconnects the graph.

Two tests on one tree

Run DFS from any node. For each node x, disc(x) is its discovery time, and low(x) is the smallest discovery time reachable from the subtree of x using tree edges plus at most one back edge.

For bridges, start a depth-first search at an arbitrary node to build the tree. An edge a → b is a bridge exactly when it is a tree edge and there is no back edge from the subtree of b to a or any ancestor of a: low(b) > disc(a).

Finding articulation points is a bit more difficult, but the tree helps again. If x is the root, it is an articulation point exactly when it has two or more children. If x is not the root, it is an articulation point exactly when it has a child whose subtree has no back edge to an ancestor of x.

In the example tree, the bridges are 2–5 and 3–7. The articulation points are 1, 2, and 3. Node 4 is not an articulation point, because node 8 has a back edge to 2, an ancestor of 4.

12.4.2

Eulerian Subgraphs

An Eulerian subgraph contains all the nodes and a subset of the edges such that every node has even degree. Consider counting the Eulerian subgraphs of a connected graph. There is a simple formula: there are always 2k of them, where k is the number of back edges in the depth-first search tree.

Note that k = m − (n − 1) where n is the number of nodes and m is the number of edges. The depth-first search tree helps to understand why this formula holds. Consider any fixed subset of back edges in the depth-first search tree. To create an Eulerian subgraph that contains these edges, we need to choose a subset of the tree edges so that each node has an even degree. To do this, we process the tree from bottom to top and always include a tree edge in the subgraph exactly when it points to a node whose degree is even with the edge. Then, since the sum of degrees is even, also the degree of the root node will be even.

Thus, every subset of back edges extends to exactly one Eulerian subgraph, and there are 2k subsets.

2k, where k = m − n + 1

For the graph in the figure, n = 5 and m = 7, so k = 3 and there are 8 Eulerian subgraphs.

The deepest structure in a directed graph is a DAG of components. The deepest structure in an undirected graph is a DFS tree with back edges. Both let a hard-looking problem collapse into a simple one.
