Chapter 03 Efficiency

Efficiency

A fast algorithm is not one that runs quickly on a small test. It is one whose work grows slowly when the input grows. This chapter is about measuring that growth before writing a line of code.

3.1

Time Complexity

Time complexity is a prediction, not a measurement.

The time complexity of an algorithm estimates how much time it will use for a given input. It is written O(…), with a function in place of the dots. Usually the variable n is the size of the input: the length of an array, the number of nodes in a graph, the length of a string.

The point of the notation is that it lets us reject a slow idea before implementing it. If we know the input can be as large as n = 105, and our idea needs n2 steps, we can already tell that it will not fit a one-second limit. No compiler required.

3.1.1

Calculation Rules

Complexity is read from the shape of the code. Four rules cover most of what appears in a contest solution.

01

Straight-line code is constant

A fixed sequence of commands does not depend on the input size.

a++; b++; c = a + b; O(1)
02

A loop repeats its body

One loop over n values is O(n). With k nested loops, each running through n values, the cost is O(nk).

for (int i = 1; i <= n; i++) O(n)
03

Constants disappear

Only the order of growth is kept. The exact operation count can still differ a great deal.

3n  ·  n + 5  ·  ⌈n/2⌉ O(n)
04

Recursion is calls × cost

The total cost is the number of calls multiplied by the cost of one call. Two calls per level can change everything.

f(n-1)  ·  g(n-1); g(n-1); O(n) · O(2n)
Three loops · n = 100 all O(n)
for (i = 1; i <= 3*n; i++)
300
for (i = 1; i <= n+5; i++)
105
for (i = 1; i <= n; i += 2)
50

The loop bodies run 300, 105, and 50 times. The class is the same; the work differs by a factor of six.

O(n) + O(n2) + O(n) = O(n2)

Consecutive phases add, but only the slowest one matters. A single bottleneck decides the total.

A loop bound is not always n. A loop over n containing a loop over m costs O(nm), which is a different statement from O(n2) unless n and m are known to be the same size.

3.1.2

Common Time Complexities

Nine classes cover almost every algorithm in this book. Learn their shapes, not just their names.

Polynomial · at most O(nk)
O(1)

Constant. A direct formula or a fixed number of commands. The input size does not change the work.

direct formula
O(log n)

Logarithmic. The input is halved at each step. log2 n is the number of halvings needed to reach 1; the base is not written.

binary search
O(√n)

Square root. Slower than logarithmic, faster than linear. Since √n = n/√n, n elements split into O(√n) blocks of O(√n) elements.

blocks
O(n)

Linear. The input is scanned a constant number of times. Often the best possible, because every element may need to be read at least once.

one pass
O(n log n)

Linearithmic. Usually sorting, or a data structure whose operation costs O(log n) for each of n elements.

sorting
O(n2)

Quadratic. Usually two nested loops, or all pairs of the input elements.

pairs
O(n3)

Cubic. Usually three nested loops, or all triplets of the input elements.

triplets
Beyond polynomial
O(2n)

Exponential. All subsets of the input. Each element is either included or left out; there are 2n choices.

subsets
O(n!)

Factorial. All permutations of the input. The first element can be any of n, the next any of n − 1, and so on.

permutations

An algorithm is polynomial if its complexity is at most O(nk) for a constant k. Polynomial roughly means that large inputs remain possible. The important exception on the list is 2n and n!, and there are many problems for which no polynomial algorithm is known at all — the NP-hard problems.

3.1.3

Estimating Efficiency

A modern computer can perform some hundreds of millions of simple operations in a second. Take 108 per second as a working estimate.

Suppose the time limit is one second and the input size is n = 105. An O(n2) algorithm performs about (105)2 = 1010 operations. That is at least some tens of seconds, so the algorithm is too slow. An O(n log n) algorithm needs only about 105 log 105 ≈ 1.6 · 106 operations, and will fit comfortably.

The estimate also works in the other direction: given n, it suggests what complexity to aim for. A large input rules out whole families of approaches before any code is written.

These are rules of thumb, not guarantees. Hardware, language, and hidden constants all move the line.

A complexity is still only an estimate, because it hides constant factors. An O(n) algorithm may perform n/2 or 5n operations, and that difference has a real effect on the clock. Use the class to rule out the impossible; use the constants to choose between the survivors.

Match the input size to the class, then let the constants decide the rest.

3.1.4

Formal Definitions

The notation has a precise meaning: an upper bound that holds for sufficiently large inputs.

O

Upper bound

A complexity is O(f(n)) if there are constants c and n0 such that the algorithm performs at most c · f(n) operations for every n ≥ n0.

Ω

Lower bound

A complexity is Ω(f(n)) if there are constants c and n0 such that the algorithm performs at least c · f(n) operations for every n ≥ n0.

Θ

Exact bound

A complexity is Θ(f(n)) if it is both O(f(n)) and Ω(f(n)). The growth is bounded on both sides.

Technically true, practically misleading

A single loop over n values is O(n), but it is also technically O(n2). The definition only asks for an upper bound, and n ≤ n2 for large n. Nobody writes the weaker bound, because the notation is used to give an accurate estimate, not merely a valid one. The better bound is O(n), and here it is also Θ(n).

The notation is not only for running time. An array may contain O(n) values; an algorithm may consist of O(log n) rounds. The same order-of-growth language applies whenever a quantity depends on an input size.

3.2.1

Maximum Subarray Sum

Given an array of n numbers, find the largest possible sum of a sequence of consecutive values.

The problem is only interesting when the array may contain negative values. Otherwise the whole array would always be the answer. In the example below, the best subarray is [2, 4, −3, 5, 2], with sum 10.

01234567
−1 2 4 −3 5 2 −5 2
maximum-sum subarray2 + 4 − 3 + 5 + 2 = 10

Hover or focus a cell to see the running sum and the best sum after that position.

The straightforward solution fixes the first and last index of the subarray with two loops, then adds the values with a third loop. There are O(n2) subarrays and each sum costs O(n), so the total is O(n3). Removing the innermost loop is easy: when the right end moves one step, add the new value to a running sum. That gives O(n2).

The third solution removes the outer loop instead. For each position k, compute the best sum of a subarray that ends at k. Such a subarray either contains only a[k], or it extends a best subarray ending at k − 1. Keeping just those two numbers gives one pass over the input: O(n).

Why the one-pass rule is enough

Let sk be the maximum sum of a subarray ending at position k. Either that subarray is just a[k], or it is a subarray ending at k − 1 followed by a[k]. In the second case, the part ending at k − 1 should itself be the best one, otherwise replacing it would improve the sum. Hence sk = max(a[k], sk−1 + a[k]). The answer is the largest sk.

How much does the order matter in practice? The book reports the following running times for the three algorithms, measured on a modern computer with random input and excluding input reading.

3.2.2

Two Queens Problem

Given an n × n chessboard, count the ways to place two queens so that they do not attack each other.

Let q(n) be the number of valid placements. On a 3 × 3 board there are eight, so q(3) = 8. The number grows quickly: q(10) = 3,480.

The brute force tries every ordered pair of squares. There are n2 choices for the first queen and n2 − 1 for the second, so the work is O(n4). Since the number of placements grows fast, counting them one at a time is hopeless for large boards. The way forward is to count in groups.

A single queen attacks n − 1 squares horizontally and n − 1 vertically. On each diagonal it attacks d − 1 squares, where d is the length of that diagonal. With these counts, the number of squares available to the second queen can be computed in O(1) time, which gives an O(n2) algorithm: one pass over all first-queen positions.

To get an O(n) solution, relate q(n) to q(n − 1). If there are no queens on the last row or column, there are q(n − 1) placements. Otherwise a queen sits in one of the 2n − 1 positions on the last row or column; it attacks 3(n − 1) squares, leaving n2 − 3(n − 1) − 1 positions for the other queen. Finally, (n − 1)(n − 2) placements put both queens on the last row or column and were counted twice, so they must be subtracted.

q(n) = q(n − 1) + (2n − 1)(n2 − 3(n − 1) − 1) − (n − 1)(n − 2) = q(n − 1) + 2(n − 1)2(n − 2)

The recurrence fills a table of n values in O(n) time. It also simplifies to a closed form, which can be proved by induction and evaluated in O(1) time:
