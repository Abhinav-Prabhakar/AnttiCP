11.1

Number Theory

Number theory is the study of the integers. In a contest it is usually four operations: deciding what divides what, filtering the primes, taking a greatest common divisor, and doing all of it modulo m.

Every integer is built from primes, and every prime is found by division. The algorithms in this section exploit that structure so that a number such as 109 never has to be examined one candidate at a time.

Divisibility

a is a factor of b if a divides b, written a | b. The factors of 24 are 1, 2, 3, 4, 6, 8, 12, and 24.

Primality

An integer n > 1 is prime if its only positive factors are 1 and n. A number that is not prime is composite.

Factorisation

Every n > 1 has a unique prime factorisation n = p1α1p2α2 ⋯ pkαk.

11.1.1

Primes and Factors

Two functions describe a factorisation. Let τ(n) be the number of factors of n, and σ(n) the sum of its factors. For 12 the factors are 1, 2, 3, 4, 6, and 12, so τ(12) = 6 and σ(12) = 28. Both values follow directly from the exponents.

number of factors τ(n) = ∏i=1k (αi + 1)
sum of factors σ(n) = ∏i=1k (1 + pi + ⋯ + piαi) = ∏i=1k piαi+1 − 1pi − 1

If n is composite, it can be written as a · b with a ≤ √n, so it has a factor between 2 and ⌊√n⌋. Trial division therefore tests primality and finds a factorisation in O(√n) time. The factorisation routine below divides n by each prime factor as many times as it divides.

There are infinitely many primes

Suppose the primes were exactly p1, p2, …, pn. Then p1p2 ⋯ pn + 1 would be larger than every prime in the list, yet leave remainder 1 when divided by each of them. The list cannot be complete.

The prime-counting function π(n) gives the number of primes up to n. Primes are frequent: π(n) ≈ n / ln n.

The estimate is close, and it gets relatively closer as n grows.

Why αi + 1 choices

A factor of n chooses an exponent for each prime: 0, 1, …, αi occurrences of pi. The choices are independent, so the counts multiply. The sum formula is the same product applied to the geometric series 1 + p + ⋯ + pα.

11.1.3

Euclid’s Algorithm

The greatest common divisor gcd(a, b) is the largest integer dividing both. For example, gcd(30, 12) = 6. The lowest common multiple follows from it:

lcm(a, b) = abgcd(a, b) lcm(30, 12) = 360 / 6 = 60

Factoring both numbers would work, but it is slow. Euclid’s algorithm uses only the remainder:

gcd(a, b) = aif b = 0gcd(b, a mod b)if b ≠ 0

The number of steps is O(log n), where n = min(a, b). The same recursion can be extended to return coefficients x and y with ax + by = gcd(a, b). For 30 and 12, the algorithm gives 30 · 1 + 12 · (−2) = 6.

11.1.4

Modular Exponentiation

Powers modulo m are needed constantly, and the exponent can be enormous. The value xn mod m is computed in O(log n) time by halving the exponent:

xn = 1n = 0xn/2 · xn/2n evenxn−1 · xn odd

To compute x100, first compute x50; to compute that, first compute x25; and so on. Each even exponent halves, so only O(log n) multiplications are needed.

11.1.5

Euler’s Theorem

Two integers are coprime if gcd(a, b) = 1. Euler’s totient function φ(n) counts the integers between 1 and n that are coprime to n. For 10, the four values 1, 3, 7, and 9 are coprime to 10, so φ(10) = 4.

φ(n) is computed from the prime factorisation:

φ(n) = ∏i=1k piαi−1(pi − 1)

For 10 = 2 · 5, this gives 20(2 − 1) · 50(5 − 1) = 4. For 12 = 22 · 3, it gives 21(2 − 1) · 30(3 − 1) = 4.

If m is prime, every number 1, 2, …, m − 1 is coprime to m, so φ(m) = m − 1.

Euler’s theorem: if x and m are coprime, then xφ(m) mod m = 1.

For example, 74 mod 10 = 1, because 7 and 10 are coprime and φ(10) = 4. When m is prime this becomes Fermat’s little theorem, xm−1 mod m = 1. It also means an exponent can be reduced: xn mod m = xn mod (m−1) mod m for prime m.

Modular multiplicative inverse

The inverse of x modulo m is the value invm(x) with x · invm(x) mod m = 1. It exists exactly when x and m are coprime, and then

invm(x) = xφ(m)−1 mod m

For prime m this is xm−2 mod m. Division by x becomes multiplication by its inverse: 36 / 6 mod 17 = 36 · 3 mod 17, because inv17(6) = 615 mod 17 = 3.

6 · 3 mod 17
1

and 615 mod 17 = 3, so the modular exponentiation routine from 11.1.4 computes the inverse.

Where the exponent reduction comes from

Write n = q(m−1) + r. Then xn = (xm−1)q · xr. Fermat’s theorem makes the first factor 1 modulo the prime m, leaving xr.

11.1.6

Solving Equations

A Diophantine equation asks for integers x and y such that ax + by = c. For 5x + 2y = 11, one solution is x = 3, y = −2. Extended Euclid solves the case c = gcd(a, b); a solution exists exactly when gcd(a, b) divides c.

A worked equation

Solve 39x + 15y = 12. First gcd(39, 15) = 3, and 3 | 12, so solutions exist. Extended Euclid gives 39 · 2 + 15 · (−5) = 3. Multiplying by 4 gives 39 · 8 + 15 · (−20) = 12, so (x, y) = (8, −20).

11.2

Combinatorics

Combinatorics counts combinations without generating them. The whole subject is a set of shortcuts for a question that would otherwise need a list.

How many ways can we choose, arrange, or divide a set? The tools below answer that for subsets, parenthesis strings, unions of sets, symmetric objects, and labelled trees.

11.2.1

Binomial Coefficients

The binomial coefficient C(n, k) is the number of ways to choose a subset of k elements from a set of n elements. For 5 and 3 the answer is 10:

C(5, 3) = 10

Recursion (nk) = (n−1k−1) + (n−1k)

Either the element x is chosen, or it is not.

Factorials (nk) = n!k!(n−k)!

From n! permutations, divide by the order inside and outside the subset.

Symmetry and sum (nk) = (nn−k)
Σk=0n (nk) = 2n

Choosing a subset is choosing its complement. Summed over every k, the choices count each element’s in/out decision.

11.2.2

Catalan Numbers

The Catalan number Cn counts valid parenthesis expressions with n left and n right parentheses. For n = 3 there are five:

Recurrence
Cn = Σi=0n−1 Ci Cn−i−1

Split the expression after the first part becomes a complete valid expression. The first part contains i+1 pairs, the second n−i−1. The base case is C0 = 1.

Closed form
Cn = 1n+1 (2nn)

Of the C(2n, n) strings, the invalid ones can be reflected at their first bad prefix. That is a bijection with strings of n+1 left and n−1 right parentheses, of which there are C(2n, n+1).

Cn also counts binary trees of n nodes, and general rooted trees of n+1 nodes. For n = 3 both counts are five.

11.2.3

Inclusion–Exclusion

Inclusion–exclusion computes the size of a union from the sizes of the intersections, and vice versa. For two sets,

|A ∪ B| = |A| + |B| − |A ∩ B|

Counting derangements

A derangement of {1, 2, …, n} is a permutation in which no element stays in its place. For n = 3 there are two: (2, 3, 1) and (3, 1, 2). Let Xk be the set of permutations that keep k fixed. Then the derangements are everything outside X1 ∪ X2 ∪ X3.

The three sets, for n = 3
X1(1,2,3) (1,3,2)
X2(1,2,3) (3,2,1)
X3(1,2,3) (2,1,3)
|X1 ∪ X2 ∪ X3|= 2 + 2 + 2 − 1 − 1 − 1 + 1 = 4
derangements= 3! − 4 = 2

An intersection of c distinct sets has (n−c)! elements: those c positions are fixed, the rest are free.

There is also a direct recurrence. Let f(n) be the number of derangements. Then f(1) = 0, f(2) = 1, and for n > 2,

f(n) = (n−1)(f(n−2) + f(n−1)) choose what replaces 1: swap with 1, or continue without it
11.2.4

Burnside’s Lemma

Burnside’s lemma counts combinations up to symmetry. If there are n ways to move a combination and c(k) combinations stay unchanged under the kth move, the number of distinct combinations is

1n Σk=1n c(k)

For a necklace of n pearls with m colours, a rotation by k steps preserves exactly mgcd(k,n) necklaces: the pearls split into blocks of size gcd(k, n), and each block must share one colour.

1n Σk=0n−1 mgcd(k,n)

For n = 4 and m = 3: the identity fixes 34 necklaces, a quarter-turn fixes 31, a half-turn fixes 32, and a three-quarter turn fixes 31.

11.2.5

Cayley’s Formula

There are nn−2 distinct labelled trees on n nodes. For n = 4 that is 42 = 16. The proof uses a code that describes a tree uniquely.

A Prüfer code is a sequence of n−2 numbers. For the tree above, removing leaf 1 writes 4; removing leaf 3 writes 4; removing leaf 4 writes 2. The remaining two nodes need no code.

Every tree produces a code, and every code of length n−2 with values 1…n produces exactly one tree. Since there are nn−2 such sequences, that is the number of labelled trees.

11.3

Matrices

A matrix is a two-dimensional array with arithmetic. In a contest, its real power is compression: one matrix multiplication can advance a whole recurrence by one step.

A matrix of size a × b has a rows and b columns. The notation A[i, j] means row i, column j. A vector is a matrix of size n × 1, and a square matrix has equal dimensions.

The transpose AT swaps rows and columns: AT[i, j] = A[j, i].

11.3.1

Matrix Operations

Matrices of the same size add element by element, and a scalar multiplies every element. Multiplication is the operation that matters: AB is defined when A is a × n and B is n × b, and the result is a × b.

AB[i, j] = Σk=1n A[i, k] · B[k, j]

Associative, not commutative

A(BC) = (AB)C, so a chain of multiplications can be grouped freely. But usually AB ≠ BA: the order of the factors is part of the meaning.

The identity matrix I has ones on the diagonal and zeros elsewhere. Multiplying by I changes nothing: AI = IA = A.

11.3.2

Linear Recurrences

A linear recurrence fixes k initial values and computes each later value from the previous k:

f(n) = c1f(n−1) + c2f(n−2) + ⋯ + ckf(n−k)

Dynamic programming computes f(n) in O(kn) time. A matrix computes it in O(k3 log n) time. The idea is to make the state a vector of k consecutive values and let one matrix advance the window.

Fibonacci numbers

For f(0) = 0, f(1) = 1 and f(n) = f(n−1) + f(n−2), the transition matrix is

X = 0111

so that X · [f(i), f(i+1)]T = [f(i+1), f(i+2)]T. Therefore

[f(n), f(n+1)]T = Xn · [0, 1]T

and Xn takes O(log n) matrix multiplications by repeated squaring.

One step, exactly
0111 · 58 = 813

f(5) = 5 and f(6) = 8 become f(6) = 8 and f(7) = 13.

The general case

For a recurrence of order k, the state vector holds f(i), …, f(i+k−1). The first k−1 rows of X simply shift the window; the last row holds the coefficients.

The matrix is k × k, so each multiplication costs O(k3), and f(n) costs O(k3 log n).

11.3.3

Graphs and Matrices

Let M be the adjacency matrix of an unweighted directed graph. Then (Mn)[a, b] is the number of paths from a to b with exactly n edges. A node may repeat.

Weighted graphs

The same idea finds the shortest path of exactly n edges if multiplication is redefined. Replace the sum with a minimum and the product with a sum:

AB[i, j] = mink (A[i, k] + B[k, j])

Now matrix powers minimise path lengths. Missing edges are ∞, and the identity matrix for this operation has 0 on the diagonal and ∞ elsewhere.

From the book’s example

The minimum length of a 4-edge path from 2 to 5 is 8, using 2 → 1 → 4 → 2 → 5.

M4[2, 5] = 2 unweighted · number of walks

11.4

Probability

A probability is a number between 0 and 1. The work is in finding the right sample space, not in the arithmetic.

Probabilities can be counted with combinatorics or generated step by step. The same two views — sets and processes — lead to expectation, Markov chains, and randomised algorithms.

Three cards, one value

Draw the top three cards from a shuffled deck. What is the probability that all three have the same value? Count the favourable outcomes: 13 values, and C(4,3) suit choices for each. There are C(52,3) total draws.

13 · C(4,3)C(52,3) = 1425

11.4.1

Working with Events

An event is a subset of the possible outcomes. When a die is thrown, the event “the outcome is even” is A = {2, 4, 6}, and P(A) is the sum of the probabilities of its outcomes.

complementP(Ā) = 1 − P(A)

At least one six in ten throws: 1 − (5/6)10.

unionP(A ∪ B) = P(A) + P(B) − P(A ∩ B)

For disjoint events the last term is zero.

intersectionP(A ∩ B) = P(A)P(B | A)

Independent events satisfy P(A ∩ B) = P(A)P(B).

11.4.2

Random Variables

A random variable is a value produced by a random process. The sum of two dice is one: P(X = 10) = 3/36, from [4, 6], [5, 5], and [6, 4]. The expected value is the probability-weighted average

E[X] = Σx P(X = x) · x

Empty boxes

Place n balls randomly in n boxes. A single box is empty when all n balls avoid it, which happens with probability ((n−1)/n)n. By linearity, the expected number of empty boxes is

E = n · (n−1n)n

For n = 2 the four placements give 0, 0, 1, 1 empty boxes, so the expectation is 1/2.

11.4.3

Markov Chains

A Markov chain is a random process with states and transition probabilities. Each floor of a building can be a state: from floor 1 we always go up, from floor n always down, and elsewhere we go up or down with probability 1/2.

The probability distribution after k steps is a vector [p1, …, pn] whose entries sum to 1. Starting at floor 1 gives [1, 0, 0, 0, 0], then [0, 1, 0, 0, 0], then [1/2, 0, 1/2, 0, 0].

Dynamic programming updates the vector in O(n2m) time for m steps. A transition matrix does the same in O(n3 log m) — useful when m is large.

Randomized Algorithms

Randomness can solve problems that have nothing to do with probability. Two kinds of guarantee are useful:

Monte Carlo

May be wrong

The answer can be incorrect, with a small probability. Repeating the algorithm with fresh randomness makes the error probability smaller.

verifying matrix multiplication in O(n2)

Order statistics

Choose a random pivot x, partition the array around it, and recurse into the side containing position k. The expected size halves each time: n + n/2 + n/4 + ⋯ = O(n). The worst case is O(n2), but it is very unlikely.

Verifying a matrix product

To test AB = C, choose a random vector X and compare A(BX) with CX. Both products take O(n2) time. A mismatch is certain to be detected; a false match is possible but unlikely.

Graph colouring

Colour each node independently at random. Each edge has both endpoints differently coloured with probability 1/2, so the expected number of such edges is m/2. Generate colourings until one reaches that bound.

11.5

Game Theory

Two players, alternating moves, no randomness, complete information. A position is winning if some move hands the opponent a losing position; otherwise it is losing.

This one rule classifies every finite impartial game. Nim gives the arithmetic that makes the classification quick, and the Sprague–Grundy theorem extends it to games that look nothing like nim.

11.5.1

Game States

Start with a heap of n sticks. Each move removes 1, 2, or 3 sticks, and the player who takes the last stick wins. The states are 0, 1, …, n. State 0 is losing (no move), states 1–3 are winning (take everything), and state 4 is losing because every move leaves 1–3.

A divisibility game

In state k, remove any x < k that divides k. From 8 the moves are 1, 2, and 4; from 7 only 1. State 1 is losing. The classification alternates: every even state is winning, every odd state is losing.

Why? An even state can remove 1 to reach an odd state; every move from an odd state removes an odd divisor (since all divisors of an odd number are odd) and therefore lands on an even state. Induction from 1 finishes the argument.

11.5.2

Nim Game

Nim has n heaps. A move chooses one heap and removes any positive number of sticks from it. The player who takes the last stick wins. A state is [x1, x2, …, xn], and the empty state is losing.

The classification is one number. Let the nim sum be

s = x1 ⊕ x2 ⊕ ⋯ ⊕ xn

States with s = 0 are losing; all others are winning. For [10, 12, 5], the sum is 10 ⊕ 12 ⊕ 5 = 3, so the state is winning.

A winning move exists whenever some heap satisfies xi ⊕ s < xi. Change that heap to xi ⊕ s. Such a heap always exists: take one with a 1 in the position of the leftmost 1-bit of s.

Misère nim

If the player who takes the last stick loses, play the normal strategy until every heap has at most one stick after the next move. Then change the parity: leave an odd number of one-stick heaps. The turning point is always reached, and it is winning because exactly one heap still has more than one stick, so the nim sum is not zero.

11.5.3

Sprague–Grundy Theorem

The theorem applies to games with two alternating players, moves that do not depend on whose turn it is, a certain end, complete information, and no randomness. Each state receives a Grundy number that behaves exactly like the size of a nim heap.

The mex rule

The Grundy number of a state is the smallest nonnegative integer not among the Grundy numbers of its options:

g = mex({g1, g2, …, gn})

For example, mex({0, 1, 3}) = 2. A state with no moves has g = 0, because mex(∅) = 0. A Grundy number of 0 is losing; a positive one is winning.

If a game consists of independent subgames, its Grundy number is the nim sum of the subgames’ Grundy numbers.

The theorem asks for
  • two players
  • alternating moves
  • same moves for both
  • no randomness
  • complete information
  • guaranteed end

A game may have moves to states with larger Grundy numbers; the opponent can cancel them, so the nim strategy still works.

The theorem turns a game into arithmetic. Three mazes with Grundy numbers 2, 3, and 3 have nim sum 2 ⊕ 3 ⊕ 3 = 2, so the first player wins. Moving two steps up in the first maze changes its value to 0, leaving 0 ⊕ 3 ⊕ 3 = 0 for the opponent.

Primes, binomial coefficients, matrix powers, distributions, and Grundy numbers are all compressions: each one replaces a large explicit object with a small invariant that is enough to answer the question.
