10.1

Basic Techniques

Root a tree, and every path becomes two ascents to a highest point.

A tree is a connected acyclic graph with n nodes and n − 1 edges. Removing any edge divides it into two components, and adding any edge creates a cycle. There is always a unique path between two nodes, and the leaves are the nodes with only one neighbour.

  • connected
  • acyclic
  • n − 1 edges
  • unique path

In a rooted tree one node is appointed the root, and all other nodes are placed underneath it. The lower neighbours of a node are its children, and its upper neighbour is its parent. Every node except the root has exactly one parent. The structure is recursive: each node is the root of a subtree containing itself and all nodes below it.

7edges
4leaves
1root

A tree has no cycles, so a traversal never has to guard against visiting a node twice — only against walking back along the edge it came from.

10.1.1

Tree Traversal

Tree traversal is easier to implement than general graph traversal, because there are no cycles and no node can be reached from more than one direction.

The usual starting point is a depth-first search from an arbitrary node. The recursive function takes the current node s and the previous node e. The parameter e is the only guard needed: the search never moves back to where it came from. The first call uses e = 0, since there is no previous node.

Dynamic programming fits naturally into the same traversal. To count the nodes in every subtree, initialise sz[s] = 1, recurse into each child, then add the child's count. Each node is visited once, so the whole computation is O(n).

A binary tree
pre-order 1  2  4  5  6  3  7

root, left, right

in-order 4  2  6  5  1  3  7

left, root, right

post-order 4  6  5  2  7  3  1

left, right, root

Pre-order and in-order together determine the tree uniquely. So do post-order and in-order. Pre-order and post-order alone may leave more than one tree consistent with the orders.

10.1.2

Calculating Diameters

The diameter of a tree is the maximum length of a path between two nodes. Both algorithms below find it in O(n) time.

First algorithm

Root, then look up

Every path in a rooted tree has a highest point. For each node x, compute toLeaf(x), the longest path from x down to a leaf, and maxLength(x), the longest path whose highest point is x. The answer is the largest maxLength.

Choose the two children a and b with the largest toLeaf values; then maxLength(x) = toLeaf(a) + toLeaf(b) + 2. If x has fewer than two children, use the only child's value plus one, or 0 when x is a leaf.

Second algorithm

Two sweeps

Choose an arbitrary node a and find the farthest node b from it. Then find the farthest node c from b. The distance between b and c is the diameter.

Both searches are ordinary depth-first searches, so the whole method is two linear passes. It is short, elegant, and easy to implement once the tree is stored as adjacency lists.

The seven-node example

Where is the path highest?

The path 6 → 2 → 1 → 4 → 7 has length 4, and node 1 is its highest point.

Why the two sweeps work

Draw the diameter horizontally and let every other node hang from it. Let x be the point where the path from the arbitrary start a joins the diameter. The farthest node from a is b, c, or another node at least as far from x as either of them. So the first sweep always returns a valid endpoint of some diameter.

The second sweep measures the farthest distance from that endpoint, which is the diameter itself.

10.1.3

All Longest Paths

For every node x, compute the maximum length of a path that begins at x. The largest of these values is the diameter, so this generalises the previous problem — still in O(n) time.

Root the tree arbitrarily. A longest path from x either goes downwards through a child, or upwards through its parent p and then somewhere else. The downward part is a standard subtree DP. The upward part is the subtle one: the best path from p may immediately re-enter the subtree of x, which would repeat an edge.

That is why each node stores the lengths of its two best downward paths, in different directions: maxLength1(x) and maxLength2(x). If the parent's best path uses x, use the second-best value instead.

The two cases, precisely

To find the best path from x upwards through its parent p: if the path realising maxLength1(p) goes through x, the answer is maxLength2(p) + 1; otherwise it is maxLength1(p) + 1.

Both maxima are computed during the same post-order traversal that computes subtree sizes, so the rerooting pass adds only linear work.

10.2

Tree Queries

A rooted tree turns subtree queries into intervals and path queries into ascents.

The queries in this section are typically about subtrees and paths. With a little preprocessing they can be answered in constant or logarithmic time instead of walking the tree for every query.

  • kth ancestorO(log k)
  • subtree sumO(log n)
  • lowest common ancestorO(log n)
  • distance between nodesO(log n)
10.2.1

Finding Ancestors

The kth ancestor of a node x is the node reached by moving k levels up. Writing ancestor(x, k), the answer is 0 when no such ancestor exists.

Walking up one edge at a time costs O(k), which can be O(n) — too slow when a tree is a long path and there are many queries. The fix is to precompute jumps whose lengths are powers of two. After O(n log n) preprocessing, any ancestor(x, k) is answered in O(log k) time by writing k as a sum of powers of two.

Why powers of two are enough

Every positive integer has a unique binary representation. To move k levels, scan the bits of k and apply the precomputed jump for each set bit. A jump of 2b is read directly from up[b][x], and the next jump starts from the node just reached.

The table has one row per power of two. Since a node has fewer than n ancestors, only O(log n) rows are needed.

10.2.2

Subtrees and Paths

A tree traversal array lists the nodes in the order a depth-first search from the root visits them. Each subtree then occupies one contiguous subarray, with its root at the left end.

This single property does a lot of work. To compute the sum of values in a subtree, find the subtree's size, then sum that many consecutive array entries. Updates and queries become range operations, handled in O(log n) by a binary indexed tree or a segment tree.

A second application is path sums from the root. Store in each array position the sum of values on the path from the root to that node. When the value of a node increases by x, every path sum in its subtree increases by x — which is a range addition over the subtree interval. A difference array plus a binary indexed tree supports the range addition and the point query in O(log n).

Range add, point query

Represent the array as differences. Adding x to every position in [l, r] means adding x at l and subtracting x at r + 1. A prefix sum of the difference array then gives the current value at any single position.

The subtree interval is [tin[s], tin[s] + sz[s] − 1], so both operations stay inside one range.

10.2.3

Lowest Common Ancestors

The lowest common ancestor of two nodes is the lowest node whose subtree contains both of them. In the example tree, the lowest common ancestor of nodes 5 and 8 is node 2.

Once kth ancestors are available, an LCA query becomes a short pointer walk. First make the pointers point to nodes at the same depth by lifting the deeper one. Then move both pointers upwards together, as far as their ancestors remain different. The parent of the two final positions is the lowest common ancestor.

Start by equalising the depths. Then lift both pointers while their ancestors differ.

Distances follow immediately. With c the lowest common ancestor of a and b, the length of the path between them is depth(a) + depth(b) − 2·depth(c). For nodes 5 and 8 the depths are 3, 4 and 2, so the distance is 3 + 4 − 2·2 = 3.

The Euler tour alternative

Walk the tree with a depth-first search and append a node every time the search passes through it — not only on the first visit. A node with k children appears k + 1 times, and the array has 2n − 1 entries. Store the node id and its depth.

The lowest common ancestor of a and b is the minimum-depth node between any occurrence of a and any occurrence of b. That is a range minimum query: O(log n) with a segment tree, or O(1) after O(n log n) preprocessing on the static array.

10.2.4

Merging Data Structures

The methods so far are online: each query is answered before the next arrives. Many problems give the whole query set at once, and an offline traversal can be simpler.

One offline pattern keeps a data structure at every node. At node s, start with a structure d[s] containing only the value of s. Then merge in the structures of the children. Queries attached to s are answered as soon as its structure is complete.

The maps are merged small into large: before copying a child's map into the parent's map, swap them if the parent's map is smaller. Each value then moves to a larger map only, so it is copied O(log n) times over the whole traversal. Swapping two C++ standard library containers is constant time, so the trick costs nothing.

10.3

Advanced Techniques

Two ways to make a tree smaller: split it at a centroid, or cut it into heavy paths.

Centroid decomposition divides a tree into smaller subtrees and processes them recursively. Heavy-light decomposition represents a tree as a set of special paths, which makes path queries behave almost like array queries.

10.3.1

Centroid Decomposition

A centroid of a tree of n nodes is a node whose removal leaves subtrees of at most ⌊n/2⌋ nodes each. Every tree has one, and it can be found by walking towards the largest subtree until no subtree is too large.

Centroid decomposition processes all paths that pass through the centroid, removes it, and recurses on the remaining components. Each removal at least halves the component size, so there are O(log n) levels. If each level costs linear time, the whole algorithm is O(n log n).

Level 0 of 2

Node 5 is the only centroid: removing it leaves components of 2, 2 and 3 nodes.

Process every path through 5, remove it, and repeat inside each component.

The standard application is counting paths of a given length. For each centroid, count the paths that pass through it in linear time; then remove it and recurse. Every path is counted exactly once, at the first centroid it meets.

Why the recursion is shallow

After removing a centroid, every remaining component has at most half as many nodes as the component it came from. The size sequence is at most n, n/2, n/4, … so it reaches 1 in ⌈log2 n⌉ levels.

That is where the extra logarithmic factor comes from: linear work per level, logarithmic number of levels.

10.3.2

Heavy-Light Decomposition

Heavy-light decomposition divides the nodes of a tree into heavy paths, arranged so that a path between any two nodes can be covered by O(log n) subpaths of heavy paths.

Root the tree arbitrarily. Start a heavy path at the root and always continue to the child with the largest subtree; then recurse on the remaining subtrees. In the example tree this gives four paths: 1–2–6–8, 3, 4–7 and 5.

Because the heavy child is always the largest, every light edge leads to a subtree at most half the size of its parent's. A path therefore crosses only O(log n) light edges, and between them it travels along heavy paths. Each heavy path can be treated as an array and equipped with a segment tree.

The light edge 4–1 joins the two heavy subpaths. The decomposition stores each side in its own segment tree.

A path query becomes O(log n) segment-tree queries: one per heavy subpath. Each segment-tree query is itself O(log n), so the total is O(log2 n). Path updates work the same way.

When not to use it

Heavy-light decomposition is powerful, but it is not always the easiest solution. The traversal-array techniques of Sect. 10.2.2 are often enough, and they are shorter to implement. Reach for heavy-light when the query is genuinely about arbitrary paths and the simpler interval tricks do not apply.
