15.1

Square Root Techniques

A square root is a poor man’s logarithm: O(√n) is better than O(n) but worse than O(log n).

The recurring idea is to divide n elements into O(√n) blocks of O(√n) elements each, and to keep one summary value per block. The structure is simple to implement and fast enough for a surprising range of problems.

15.1.1

Data Structures

Suppose we must modify array values and find minimum values in ranges. A segment tree supports both operations in O(log n). The square-root structure takes O(√n) instead, and needs only the array and one minimum per block.

To query a range, scan the values in the first and last partial blocks, and read the stored minimum for every whole block between them. Since there are O(√n) single values and O(√n) blocks, the query is O(√n). An update changes one value and rescans only its block.

15.1.2

Subalgorithms

Some problems have two natural algorithms that fail in opposite cases. Instead of choosing one, use both as subalgorithms and decide per case which one to run.

Letter distances

An n × n grid is filled with letters. Find the minimum Manhattan distance between two squares with the same letter. For one letter c, there are two options:

Algorithm 1 All pairs O(k2)

Compare every pair of squares that contain c. Good when k is small; terrible when every square is the same letter.

Algorithm 2 Multi-source BFS O(n2)

Start a breadth-first search from all c-squares at once. Good when k is large; wasteful when most letters are rare.

pairs BFS
k ≤ xk > x

Choose x = √(n2) = n. A square handled by Algorithm 1 is compared with at most n others, and at most n letters occur more than n times — so both halves cost O(n3).

A second example

The black squares game

One square of an n × n grid is black. On each turn a white square is chosen, its distance to the nearest black square is reported, and it becomes black.

Process the turns in batches of k. Before a batch, one BFS computes the distance from every square to a black square: O(n2). During the batch, the answer is the smaller of that precomputed value and the distance to one of the at most k squares painted in this batch. With k = n there are O(n) batches, so the total is O(n3).

X is three steps from the nearest black square. After the report, X becomes black too.

15.1.3

Integer Partitions

Cut a stick of length n into integer parts. How many different lengths can appear? At most O(√n). To get as many as possible, use lengths 1, 2, …, k, whose total is k(k + 1)/2. This cannot exceed n, so k = O(√n).

Knapsack with few distinct weights

A knapsack list has integer weights summing to n. The standard algorithm is O(nk), which is O(n2) when k = O(n). But there are at most O(√n) distinct weights, so process equal weights as a group in O(n) time. The total becomes O(n√n).

String construction

Given a string of length n and a dictionary of total length m, count the ways to build the string from dictionary words. A trie over reversed words gives O(n2 + m). A second approach exploits that there are at most O(√m) distinct word lengths: store the hash of every word, and for each prefix try only lengths that occur. That is O(n√m + m) with a hash set.

15.1.4

Mo’s Algorithm

Mo’s algorithm handles many range queries on a static array. It keeps one active range and moves its two endpoints one step at a time, updating the answer in O(1) per step. The array never changes, so the queries may be answered in any order — and the trick is to choose a good one.

Divide the array into blocks of k = O(√n). Sort the queries by the block of their left endpoint, and within a block by their right endpoint. The left endpoint moves O(n) times within each of O(√n) blocks, and the right endpoint moves O(n) within each block. Both endpoints move O(n√n) steps in total.

For distinct values, keep count[x] for the active range and a running total. Adding x increments count[x], and raises the answer if it became 1; removing x decrements it, and lowers the answer if it became 0. The whole algorithm runs in O(n√n) time.

Why the ordering helps

Within one left block, all queries are sorted by right endpoint, so the right endpoint only moves forward — O(n) steps per block. The left endpoint can jump back and forth, but it always stays inside a block of size k = O(√n), so moving between consecutive queries costs O(√n). Across O(√n) blocks the total is O(n√n).

Mo’s algorithm is named after Mo Tao, a Chinese competitive programmer.[5]

15.2

Segment Trees Revisited

Until now the segment tree has been walked from the bottom up. The advanced variants are easier to write from the top down.

A range query descends from the root, stopping at nodes whose ranges are completely inside the query. This recursive shape is what makes lazy updates, sparse trees and nested trees possible.

The familiar function walks upward from two leaves:

a += n; b += n;
while (a <= b) { … a /= 2; b /= 2; }

The top-down version passes the current tree index k and its range [x, y]. If [x, y] is outside [a, b], return 0. If it is inside, return tree[k]. Otherwise continue into both halves.

Only O(log n) nodes are visited, because at each level at most two nodes are partially covered.

15.2.1

Lazy Propagation

A lazy segment tree supports range updates and range queries, both in O(log n). Each node stores the usual value s and a lazy tag z: “every value in this range should still be increased by z”.

To add u to a range, descend as usual. If a node is completely inside the update, add u to its z and stop — its children are not touched. If the node is only partially covered, recurse into the children and then recompute s from them. Before accessing a node, push its tag to both children and clear it.

One pattern, several updates

The same machinery supports adding a constant and assigning a value. It even supports adding a polynomial: give each node k + 2 values, the sum s and coefficients z0 … zk. The lazy update at position i adds p(i − a) for a polynomial p of degree k.

When a polynomial tag moves down by h positions, replace p(u) with p(u + h) — still a polynomial of the same degree. Sums of powers give the contribution of each coefficient to a node in O(1).

The shift, written out

If p(u) = t2u2 + t1u + t0, then

p(u + h) = t2u2 + (2ht2 + t1)u + t2h2 + t1h + t0.

For a range of length L, the constant term contributes z0L, and the linear term contributes z1(0 + 1 + … + L − 1) = z1L(L − 1)/2.

15.2.2

Dynamic Trees

An ordinary segment tree reserves a fixed array. A dynamic tree allocates a node only when it is actually visited. This pays off when the index range is huge but most values stay zero: a sparse tree with k operations uses O(k log n) memory instead of O(n).

A node stores its value, its range [x, y], and pointers to its children. The tree starts as a single zero node [0, n − 1]; each update creates at most O(log n) new nodes along one path. If all updated indices are known in advance, index compression is simpler — but not when the indices are generated online.

A dynamic implementation also gives persistence almost for free. An update copies the O(log n) nodes on its path and leaves the rest shared with the previous version. Each historical tree is then identified by its root pointer, and previous versions can still be queried.

15.2.3

Data Structures in Nodes

A node need not store a single number. It can store a whole data structure describing its range. To count occurrences of a value x in [a, b], give every segment-tree node a map from values to frequencies. Query the O(log n) nodes that cover the range and add their answers.

Each map operation costs O(log n), so a query is O(log2 n). The tree uses O(n log n) memory: O(log n) levels, each holding n entries in total.

15.2.4

Two-Dimensional Trees

A two-dimensional segment tree processes rectangle queries. Build a segment tree over the columns, and give every column node another segment tree over the rows. A subarray sum touches O(log n) column nodes, and each of those answers in O(log n), so both queries and updates are O(log2 n).

The memory is O(n2): O(n) column nodes, each with a row tree of O(n) nodes. That is the price of asking two-dimensional questions without scanning a row.

15.3

Treaps

A treap stores an array as a binary tree whose inorder walk is the array and whose weights form a heap.

Each node carries a value and a random weight. The weights are smaller toward the root, and the values appear in array order from left to right. Random weights keep the height O(log n) with high probability — and make splitting and merging cheap.

In the example, the root has weight 1 and value D. Its left subtree holds three nodes, so D is the array element at position 3. The weights are not chosen by hand: every new node receives a random weight, and the shape follows.

15.3.1

Splitting and Merging

Split creates two treaps containing the first k elements and the rest. Walk down from the root. If the current node belongs to the left result, keep it and its left subtree, and recurse into its right subtree. Otherwise keep it and its right subtree, and recurse into its left subtree. Only one path is visited.

Merge concatenates two treaps. Compare the weights of their roots; the smaller weight becomes the root of the result, and the other treap is merged into the appropriate subtree. The recursion follows a single root-to-leaf path.

In the example, splitting after the fifth element follows D → C → W → I. Merging the two halves in the opposite order turns S A N D W I C H into I C H S A N D W.

15.3.2

Implementation

The structure needs one extra field: size, the number of nodes in the subtree. Both operations update it on the way back up. With this field, size(treap->left) < k tells us whether the split point lies in the left subtree.

The final lines of the example build the array [1, 2, 3, 4], split it into two halves of size two, and merge them in the opposite order. The result is [3, 4, 1, 2] — a rotation of the array in O(log n) expected time.

15.3.3

Additional Techniques

A treap can maintain more than size: the sum of a subtree, its minimum, or any value that combines associatively. With split and merge this turns the treap into a fully dynamic sequence — insert, delete, reverse, and move whole blocks.

Reversal is the special trick. Swapping the left and right child of every node reverses the array, but doing it eagerly is too slow. Store a “reverse pending” flag and swap lazily, exactly like a lazy segment tree.

15.4

Dynamic Programming Optimization

The hard part of a dynamic program is often not the state — it is the transition that tries every previous state.

Three techniques remove that inner loop when the cost function has the right shape: the convex hull trick for linear functions, divide and conquer optimization for monotone split points, and Knuth’s optimization for interval costs.

15.4.1

Convex Hull Trick

Given n lines f(x) = ax + b, we want the minimum value at a query point x. The lower envelope of the lines divides the x-axis into ranges; in each range one line is minimal. A line appears in at most one range, so there are at most n ranges. Binary search over the ranges gives O(log n) per query, or O(1) amortized when the queries arrive in increasing order.

The example uses f1(x) = x + 2, f2(x) = x/3 + 4, f3(x) = x/6 + 5 and f4(x) = −x/4 + 7. At x = 4 the minimum is f2(4) = 16/3.

15.4.2

Divide and Conquer Optimization

We must divide a sequence s1 … sn into k consecutive subsequences. A cost function cost(a, b) prices the block sa … sb. Let solve(i, j) be the minimum total cost of dividing the first i elements into j blocks. Then

solve(i, j) = min1 ≤ p ≤ i [ solve(p − 1, j − 1) + cost(p, i) ].

Trying every p gives O(n2k). If cost satisfies the quadrangle inequality

cost(a, c) + cost(b, d) ≤ cost(a, d) + cost(b, c)   for a ≤ b ≤ c ≤ d,

then the smallest optimal p, written pos(i, j), is nondecreasing in i. A recursive function can compute the middle row value, then restrict the left half to [x, pos] and the right half to [pos, y]. Each call layer costs O(n), so all values for one j take O(n log n), and the whole DP takes O(nk log n).

15.4.3

Knuth’s Optimization

Knuth’s optimization applies when a sequence is split repeatedly until only single elements remain. Let cost(a, b) be the price of processing sa … sb, and solve(i, j) the minimum cost of splitting that interval into singletons:

solve(i, j) = cost(i, j) + mini ≤ p < j [ solve(i, p) + solve(p + 1, j) ].

Checking every p is O(n3). If cost is monotone and satisfies the same quadrangle inequality, then pos(i, j − 1) ≤ pos(i, j) ≤ pos(i + 1, j). Process intervals by increasing length; on round k, every pos is bounded by two values already known, so each interval costs O(1) amortized extra and the total becomes O(n2).

15.5

Miscellaneous

Four techniques that do not share a theme, except that each one rearranges a problem until an ordinary tool fits.

15.5.1

Meet in the Middle

Meet in the middle splits the search space in half, searches both halves separately, and combines the results. An O(2n) algorithm becomes O(2n/2) — the square root of the old work. In practice that moves the feasible input from about n = 20 to n = 40.

For the subset-sum question, split the set into A and B. Generate every subset sum of each half, store the sums in lists SA and SB, and look for one value from each list that adds up to x. With sorted lists, two pointers do the combination in O(2n/2) as well.

15.5.2

Counting Subsets

Let X = {0 … n − 1}, and give each subset S a value. We want, for every S, the sum of the values of all subsets of S. Define partial(S, k) as that sum with the restriction that only elements 0 … k may be removed. Then partial(S, −1) = value[S], and

partial(S, k) = partial(S, k − 1), if k ∉ S;
partial(S, k) = partial(S, k − 1) + partial(S \ {k}, k − 1), if k ∈ S.

Because the answer only depends on the previous k, one array and two nested loops suffice: O(2nn) time and O(2n) memory. The inner test s & (1 << k) decides whether element k may be removed.

15.5.3

Parallel Binary Search

Several binary searches can be cheaper together than apart. In the road-building problem, n cities start disconnected; each day one road is built. For each of k pairs, report the first day its cities are connected. One query is easy with a union-find: add roads until the pair joins.

Doing all queries separately costs O(km log n). In parallel binary search, every query keeps an interval [x, y] of possible answer days, initially [1, m]. Repeat log m times: rebuild the road network once, and for each query test the midpoint of its interval. A successful test moves the right end; a failure moves the left end. After log m rounds every interval has one day.

Each round adds m roads and checks k pairs, both with union-find, so the total is O((m + k) log n log m).

15.5.4

Dynamic Connectivity

Edges are added and removed, and after every operation we must report the number of connected components. Union-find handles additions, but it cannot undo. The offline solution turns time into a segment tree.

Each edge is alive on an interval [a, b] of steps. Add that interval to a segment tree over time, then walk the tree. Whenever an interval fully covers the current node, add its edge to a rollback union-find. At a leaf, report the component count. On the way out, undo the unions made at that node. Every edge is added and removed O(log q) times, so the total is O((m + q) log q log n).

Every technique here is a trade: blocks for simplicity, tags for deferred work, random weights for balance, convexity for speed, and a second list whenever one search space is too large. The toolbox is complete; the problems are not.
