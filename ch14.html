Chapter 14 Indexing text

String Algorithms

Hashing turns a string into a number. The Z-algorithm and suffix arrays keep the text itself and answer the same questions exactly. Together they make text searchable at scale.

14.1

Basic Topics

Almost every string algorithm is a way of not comparing more characters than necessary.

Throughout the chapter, we assume that all strings are zero indexed. For example, a string s of length n consists of characters s[0], s[1], …, s[n−1]. A substring is a sequence of consecutive characters in a string. We use the notation s[a…b] for the substring from position a to position b. A prefix is a substring that contains the first character of a string, and a suffix one that contains the last. A subsequence is any sequence of characters in a string in their original order.

NVELO occupies positions 1–5, with no gaps.

substring consecutive characters, s[a…b]
prefix s[0…k], always starts at the beginning
suffix s[k…n−1], always ends at the end
subsequence characters in order, gaps allowed

All substrings are subsequences, but not the reverse: NVELO is a substring, NEP a subsequence. Comparing two length-n strings costs O(n) in the worst case — the rest of the chapter is about paying less.

14.1.1

Trie Structure

A trie is a rooted tree that maintains a set of strings. Each string is stored as a chain of characters from the root. Strings with a common prefix share a chain in the tree. For example, this trie holds the set {CANAL, CANDY, THE, THERE}. The four words need only eleven edges — the second A in CANAL and the Y in CANDY branch from the same CAN.

A circle marks a node where a string ends. After building a trie, we can check whether it contains a given string by following its chain from the root. We can also add a string by following its chain and adding nodes where it runs out. Both operations work in O(n) time, where n is the length of the string.

Choose a query to follow its chain from the root.

Storing a trie

A trie can be stored in an array int trie[N][A], where N is the maximum number of nodes (the maximum total length of the strings) and A is the alphabet size. Nodes are numbered 0, 1, 2, … with the root at 0, and trie[s][c] gives the next node when we move from node s by character c.

We can extend the trie structure in several ways. For example, suppose queries ask for the number of strings with a certain prefix. We can answer efficiently by storing at each node the number of strings whose chain goes through it.

14.1.2

Dynamic Programming

Dynamic programming solves many string problems. Next we will discuss two examples of such problems.

Longest common subsequence

The longest common subsequence of two strings is the longest string that appears as a subsequence in both strings. For example, the longest common subsequence of TOUR and OPERA is OR. Using dynamic programming, we can find the longest common subsequence of two strings x and y in O(nm) time, where n and m are their lengths. To do this, define lcs(i, j) as the length of the longest common subsequence of the prefixes x[0…i] and y[0…j]. Then, we can use the recurrence

lcs(i, j) = lcs(i−1, j−1) + 1   if x[i] = y[j]

lcs(i, j) = max(lcs(i, j−1), lcs(i−1, j))   otherwise

O(nm) time, O(nm) memory.

Edit distance

The edit distance (or Levenshtein distance) between two strings is the minimum number of operations that turn the first string into the second. The allowed operations are to insert, remove, or modify a character. For example, the edit distance between LOVE and MOVIE is 2, because we can first perform the operation LOVE → MOVE (modify) and then the operation MOVE → MOVIE (insert).

edit(a, b) = min( edit(a, b−1) + 1, edit(a−1, b) + 1, edit(a−1, b−1) + cost )

cost(a, b) = 0 if x[a] = y[b], and otherwise cost(a, b) = 1. Again O(nm).

The last cell holds the answer: 2 — the length of OR.

14.2

String Hashing

A hash value is a fingerprint: one integer that stands in for a whole string.

Using string hashing we can check whether two strings are equal by comparing their hash values. A hash value is an integer calculated from the characters of the string. Equal strings have equal hash values, so we can compare strings by their hashes.

A B A C B → 40hash value
14.2.1

Polynomial Hashing

A usual implementation of string hashing is polynomial hashing: the hash value of a string s of length n is

(s[0]An−1 + s[1]An−2 + ⋯ + s[n−1]A0) mod B

For example, let us calculate the hash value of ABACB. The character codes of A, B, and C are 65, 66, and 67. Then, we need to fix the constants; suppose that A = 3 and B = 97. Thus, the hash value is 40.

14.2.2

Applications

Hashing solves many string problems because it compares arbitrary substrings in O(1) time. Often we can take a brute force algorithm and make it efficient with hashing.

01 · Pattern matching

Find every occurrence

A fundamental string problem is the pattern matching problem: given a string s and a pattern p, we find the positions where p occurs in s. The pattern ABC occurs at positions 0 and 5 in the string ABCABABCA. A brute force algorithm checks every position where p may occur in s and compares character by character, in O(n2) time. Hashing makes each comparison O(1), which brings the algorithm down to O(n).

Brute force O(n2) → hashing O(n)

02 · Distinct substrings

Count what repeats

Consider counting the distinct substrings of length k in a string. For example, the string ABABAB has two distinct substrings of length 3: ABA and BAB. With hashing, we hash each substring and reduce the problem to counting distinct integers in a list, which takes O(n log n) time.

O(n log n) after O(n) preprocessing

03 · Minimal rotation

Start at the best place

A rotation is created by repeatedly moving the first character to the end of the string. For example, the rotations of ATLAS are ATLAS, TLASA, LASAT, ASATL, and SATLA, and the minimal rotation is ASATL. We can solve it by combining string hashing and binary search. First, binary search finds the length of their common prefix, which gives the lexicographic order of two strings in logarithmic time. Then the next character after the common prefix determines the order. Then we build a string with two copies of the original (e.g., ATLASATLAS) and scan its length-n substrings, keeping the minimal one. Since each comparison can be done in O(log n) time, the algorithm works in O(n log n) time.

O(n log n) overall

14.2.3

Collisions and Parameters

An evident risk when comparing hash values is a collision: two strings with different contents but equal hash values. An algorithm that relies on hashes then concludes the strings are equal, though they are not, and may give incorrect results. Collisions are always possible, because there are more different strings than different hash values. However, the probability is small if A and B are carefully chosen.

1

x is compared with y. The probability of a collision is 1/B assuming that all hash values are equally probable.

2

x is compared with strings y1, y2, …, yn. The probability of one or more collisions is 1 − (1 − 1/B)n.

3

All pairs of strings x1, x2, …, xn are compared with each other. The probability of one or more collisions is 1 − B(B−1)⋯(B−n+1)/Bn. This is the birthday paradox.

Using such constants, the long long type can be used when calculating hash values, because the products AB and BB will fit in long long.

Table 14.1 · n = 106

Every pair among a million strings: with B ≈ 109 a collision is certain. This is the birthday paradox — and the reason to use two hashes.

Making collisions negligible

We can make collisions less likely by calculating several hash values with different parameters. It is unlikely that a collision would occur in all hash values at the same time. For example, two hash values with B ≈ 109 correspond to one with B ≈ 1018, which makes the probability of a collision very small. Some people use constants B = 232 and B = 264, which is convenient because 32- and 64-bit integer operations are calculated modulo 232 and 264. However, this is a bad choice: one can construct inputs that always collide when constants of the form 2x are used.

The table shows that in Scenarios 1 and 2, the probability of a collision is negligible when B ≈ 109. In Scenario 3 the situation is very different: a collision will almost always happen when B ≈ 109.

14.3

Z-Algorithm

The Z-array records, at every position, how much of the string's own beginning repeats there.

The Z-array z of a string s of length n contains for each k = 0, 1, …, n−1 the length of the longest substring of s that begins at position k and is a prefix of s. Thus z[k] = p means s[0…p−1] equals s[k…k+p−1], but s[p] and s[k+p] differ (or the string ends at k+p).

14.3.1

Constructing the Z-Array

Next we describe an algorithm, called the Z-algorithm, which constructs the Z-array in O(n) time. It calculates values from left to right, using information already stored in the array and comparing characters when needed. To do this efficiently, it maintains a range [x, y] such that s[x…y] is a prefix of s, z[x] is known, and y is as large as possible.

  1. 1

    y < k. We have no information about position k, so we compute z[k] character by character.

  2. 2

    y ≥ k and k + z[k−x] ≤ y. Here z[k] = z[k−x], because s[0…y−x] equals s[x…y] and we stay inside the [x, y] range.

  3. 3

    y ≥ k and k + z[k−x] > y. Here z[k] ≥ y−k+1. But we know nothing after y, so we compare characters starting at y−k+1 and y+1.

The algorithm works in O(n) time: whenever two characters match in a comparison, y increases. Thus the total work needed for comparing substrings is only O(n).

14.3.2

Applications

The Z-algorithm provides an alternative way to solve many string problems also solvable with hashing. Unlike hashing, it always works, with no risk of collisions. In practice, choosing between them is often a matter of taste.

A border is a string that is both a prefix and a suffix of a string, but not the entire string. All borders can be found efficiently using the Z-algorithm, because a suffix at position k is a border exactly when k + z[k] = n, where n is the length of the string.

14.4

Suffix Arrays

The suffix array is the string's table of contents: every suffix, listed in lexicographic order.

The suffix array of a string describes the lexicographic order of its suffixes. Each value in the suffix array is a starting position of a suffix. For example, the suffix array of the string ABAACBAB is [2, 6, 0, 3, 7, 1, 5, 4]. It is often convenient to represent the suffix array vertically and also show the corresponding suffixes. However, the suffix array itself contains only starting positions, not characters.

Sorting the suffixes of an n-character string by comparing them directly takes O(n2 log n) in the worst case, since each comparison can scan O(n) characters. A simple and efficient way to create the suffix array of a string is prefix doubling, which works in O(n log2 n) or O(n log n) time depending on the implementation.

Compared to hashing and the Z-algorithm, the suffix array can answer several queries about different patterns, and the patterns need not be known when it is built.

14.4.1

Prefix Doubling Method

The algorithm consists of rounds numbered 0, 1, …, ⌈log2 n⌉, and round i goes through substrings whose length is 2i. During a round, each substring x of length 2i gets an integer label l(x), with l(a) = l(b) exactly when a = b, and l(a) < l(b) exactly when a < b.

How a pair becomes a label

On round i > 0, we use the labels for substrings of length 2i−1 to construct labels for length 2i. To label a substring x of length 2i, we divide it into halves a and b of length 2i−1 with labels l(a) and l(b). If the second half begins outside the string, its label is 0. First we give x the initial label (l(a), l(b)). After all substrings of length 2i have initial labels, we sort them and assign final labels 1, 2, 3, etc.

Round 2 · ABAA
AB2AA1

After round 1, l(AB) = 2 and l(AA) = 1. On round 2, the initial label for ABAA is (2, 1). Two initial labels are smaller ((1, 6) and (2, 0)), so the final label is l(ABAA) = 3.

In this example, each label is already unique after round 2, because the first four characters of the substrings completely determine their lexicographical order. The algorithm works in O(n log2 n) time: O(log n) rounds, each sorting n pairs. The final labels read in position order are 3 6 1 4 8 7 2 5 — which is exactly the inverse of the suffix array.

14.4.2

Finding Patterns

After building the suffix array, we can find the occurrences of any pattern in O(k log n) time, where n is the string length and k the pattern length. The idea is to process the pattern character by character, maintaining a range in the suffix array for the prefix processed so far. Binary search updates the range after each new character.

14.4.3

LCP Arrays

The LCP array of a string gives for each suffix a LCP value: the length of the longest common prefix of the suffix and the next suffix in the suffix array. The last suffix has no LCP value.

Next we present an efficient algorithm, due to Kasai et al., for constructing the LCP array of a string once its suffix array is built. It is based on one observation: consider a suffix whose LCP value is x. If we remove its first character, the resulting suffix has LCP value at least x−1. For example, the LCP value of the suffix BAACBAB is 2, so we know that the LCP value of the suffix AACBAB has to be at least 1. In fact, it happens to be exactly 1.

We can use this to construct the LCP array by calculating values in decreasing order of suffix length. For each suffix, we compare it with the next suffix character by character, skipping the first x−1 characters. The algorithm works in O(n) time, because only O(n) comparisons are made.

Counting distinct substrings

The LCP array also solves some advanced string problems. For example, the number of distinct substrings is the total number of substrings minus the sum of the LCP array:

n(n+1)/2 − c = 8 · 9 / 2 − 7 = 29

For example, the string ABAACBAB has 8 · 9 / 2 − 7 = 29 distinct substrings.

The suffix array answers questions the other tools cannot: many patterns, asked later, over the same text. Hashing gives a fingerprint, the Z-algorithm gives a scan, and the suffix array gives an index — the structure a search engine keeps.
