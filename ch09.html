Chapter 09 Range Queries

Range Queries

A query about a slice of an array should not cost a walk across the slice. Preprocess once, and most of the work disappears into two lookups.

9.1

Queries on Static Arrays

If the array never changes, a query can be answered from a table instead of from the array itself.

The array is preprocessed once into a second array. Every later query reads a constant number of entries from that table, so the cost of a query no longer depends on the length of the range.

This chapter begins with two static problems. A range sum query asks for the total in [a, b]; a range minimum query asks for the smallest value there. The same array can answer both, but the tables are different.

Prefix sums handle sums after O(n) preprocessing. Sparse tables handle minima after O(n log n). Both then answer in O(1), and both generalize: the prefix idea to higher dimensions, the sparse table to maximum queries with min replaced by max.

question on [3, 6]answertable
sumq(3, 6) 19 prefix sums
minq(3, 6) 1 sparse table

Both return in O(1) after preprocessing. Neither touches every value in the range.

9.1.1

Sum Queries

Let sumq(0, k) be the sum of the first k + 1 values. Store every one of those prefixes once. Then any range sum is the difference of two prefixes: sumq(a, b) = sumq(0, b) − sumq(0, a − 1).

Higher dimensions

One rectangle, four corners

In two dimensions, each entry of the prefix table is the sum of the rectangle from the upper-left corner to that cell. To get an arbitrary subarray, add the corner you want and subtract the two strips that were counted twice:

S(A) − S(B) − S(C) + S(D)

The final + S(D) corrects the overlap of the two subtracted strips. The same inclusion–exclusion pattern continues in three dimensions and beyond.

Why sumq(0, −1) is defined as zero

When a = 0, the formula asks for the prefix before the array. Defining sumq(0, −1) = 0 lets one formula cover every range, including one that starts at the first cell.

The prefix array is built in O(n) time by one left-to-right pass. Each entry is the previous entry plus the next array value; no query is involved.

9.1.2

Minimum Queries

A sparse table stores the minimum of every range whose length is a power of two. A query of any length is then covered by two such ranges, each of length k, where k is the largest power of two that does not exceed the query length. The ranges may overlap, which is harmless for a minimum.

Interactive query

Two windows, one minimum

Preprocessing is O(n log n): there are log n powers of two, and each level is built from the level below in one pass.

Why two windows are enough

If the query length is L and k is the largest power of two not exceeding L, then k ≤ L < 2k. One window of length k starts at the left edge; the other ends at the right edge. Together they cover every position, even when they overlap in the middle.

The answer is min(minq(a, a + k − 1), minq(b − k + 1, b)), and both values were precalculated.

9.2

Tree Structures

When the array can change, the table cannot simply be rebuilt. The structure has to repair a path of entries after each update.

Both structures in this section support a range query and a point update in O(log n). The Fenwick tree is the smaller, faster specialist for sums. The segment tree is the generalist: sums, minima, maxima, gcd, and bit operations all fit the same shape.

The trade is explicit: a static table can answer faster because it never has to change. A tree gives up a little query speed so that an update can be absorbed in logarithmic time.

9.2.1

Binary Indexed Trees

A Fenwick tree stores tree[k] = sumq(k − p(k) + 1, k), where p(k) = k & −k is the largest power of two that divides k. Each cell is responsible for a short suffix of the array ending at its own index. The arrays are one-indexed.

Interactive structure

Follow the low bit

Each bar spans the array cells it covers. A query walks down by clearing the lowest set bit; an update walks up by adding it.

Two loops, both logarithmic

To compute sumq(1, k), start at k, add tree[k], then replace k with k − (k & −k). Each step removes the lowest set bit, so the loop runs at most log2 n times.

To add x at position k, add x to tree[k] and then move to k + (k & −k). The visited cells are exactly the ranges that contain k.

For a range with a > 1, use the prefix difference: sumq(a, b) = sumq(1, b) − sumq(1, a − 1).

Example
array1 3 4 8 6 1 4 2
tree1 4 4 16 6 7 4 29

The query sumq(1, 7) visits 7, 6, and 4. The update at 3 visits 3, 4, and 8.

Why k & −k isolates the lowest set bit

In two's complement, −k flips every bit of k and adds one. Every bit below the lowest set bit becomes zero, and that bit becomes one; all higher bits cancel when the two values are ANDed. The result is exactly the power of two that p(k) is defined to be.

This is also why the loop bounds are logarithmic: each iteration of the query removes one set bit, and a number below n has at most log2 n of them.

9.2.2

Segment Trees

A segment tree is a binary tree over the array. Each node stores the answer for one range. A query splits its range into a small set of tree nodes; an update walks from a leaf to the root, recomputing the nodes on the way.

Interactive tree

Decompose a range

The tree is stored in an array of 2n cells. The leaves occupy tree[n] … tree[2n − 1]; the parent of tree[k] is tree[⌊k/2⌋].

The array is [5, 8, 6, 3, 2, 7, 2, 6]. Internal nodes hold sums; leaves hold the values themselves. Cell 0 is unused.

Other queries

The same tree works for any operation that can be computed from two independent halves. Replace + with min, max, gcd, &, |, or ^ and the query and update loops keep their shape.

A minimum tree can also locate the smallest element by walking down from the root: at each step, move to the child whose value is smaller. That is a binary search over the tree, still in O(log n).

Why the decomposition is short

On each level of the tree, at most two nodes are selected. The tree has log2 n levels, so a query touches at most 2 log2 n nodes.

The bottom-up loop starts with the leaf range [a + n, b + n] and moves one level up at a time, absorbing the nodes that fall outside the next range.

9.2.3

Additional Techniques

Two small techniques adapt the structures to awkward inputs: index compression shrinks a sparse set of indices into a dense array, and a difference array turns a range update into two point updates.

Index compression

Array-based structures need consecutive indices. If only a few large indices are used, most of the array would be empty. Compress the indices first: sort the indices that will appear and map each one to 0, 1, 2, … in that order.

The mapping preserves order. If a < b, then c(a) < c(b), so a range [a, b] becomes [c(a), c(b)] and every query keeps its meaning.

The original array is the prefix sum of the difference array. A range update changes one difference cell at the start and one just past the end; a Fenwick or segment tree can then carry the difference array.

Compression makes a sparse index space usable; a difference array makes range updates cheap. Neither changes the underlying structure — they change the array you give it.

Prefix sums remember every beginning. Sparse tables remember every power of two. Fenwick and segment trees remember just enough to repair themselves. A range query is never cheaper than the preprocessing that anticipates it.
