Chapter 09 Range Queries

Range Queries

A query about a slice of an array should not cost a walk across the slice. Preprocess once, and most of the work disappears into two lookups.

9.1

Queries on Static Arrays

If the array never changes, a query can be answered from a table instead of from the array itself.

In this section, the array is static: its values are never updated between the queries. Then it suffices to preprocess the array so that range queries are efficient.

This chapter discusses data structures for range queries on arrays. Typical queries are range sum queries (the sum of values) and range minimum queries (the smallest value).

First, a simple way to process sum queries uses a prefix sum array, which also generalizes to higher dimensions. Then the sparse table algorithm for minimum queries, which is somewhat more difficult. While we focus on minimum queries, maximum queries work the same way.

question on [3, 6]answertable
sumq(3, 6) 19 prefix sums
minq(3, 6) 1 sparse table

Both return in O(1) after preprocessing. Neither touches every value in the range.

9.1.1

Sum Queries

Let sumq(a, b) ("range sum query") denote the sum of array values in a range [a, b]. Any sum query can be processed by first constructing a prefix sum array. Each value equals the sum of the original array's values up to the corresponding position: position k holds sumq(0, k). The array can be constructed in O(n) time. Then, since it contains all values of sumq(0, k), any sumq(a, b) follows in O(1) time from the formula sumq(a, b) = sumq(0, b) − sumq(0, a − 1).

Higher dimensions

One rectangle, four corners

The idea also generalizes to higher dimensions. Each sum in the two-dimensional prefix sum array corresponds to a subarray that begins at the upper-left corner. The desired subarray follows from the formula:

S(A) − S(B) − S(C) + S(D)

Here S(X) is the sum of a rectangular subarray from the upper-left corner to X.

Why sumq(0, −1) is defined as zero

With sumq(0, −1) = 0, the formula sumq(a, b) = sumq(0, b) − sumq(0, a − 1) also holds when a = 0.

9.1.2

Minimum Queries

Let minq(a, b) ("range minimum query") denote the minimum array value in a range [a, b]. Next we discuss a technique that processes any minimum query in O(1) time after O(n log n) preprocessing. The method is due to Bender and Farach-Colton and often called the sparse table algorithm. The idea is to precalculate all values of minq(a, b) where b − a + 1 (the length of the range) is a power of two.

Interactive query

Two windows, one minimum

Preprocessing is O(n log n): there are log n powers of two, and each level is built from the level below in one pass.

Why two windows are enough

After this, any minq(a, b) is the minimum of two precalculated values. Let k be the largest power of two that does not exceed b − a + 1. The range [a, b] is the union of [a, a + k − 1] and [b − k + 1, b], both of length k.

The value of minq(a, b) is min(minq(a, a + k − 1), minq(b − k + 1, b)).

There are also sophisticated techniques that process range minimum queries in O(1) time after only O(n) preprocessing, but they are beyond this book's scope.

9.2

Tree Structures

When the array can change, the table cannot simply be rebuilt. The structure has to repair a path of entries after each update.

This section presents two tree structures that process range queries and update array values in logarithmic time. First, we discuss binary indexed trees, which support sum queries; then segment trees, which also support several other queries.

The trade is explicit: a static table can answer faster because it never has to change. A tree gives up a little query speed so that an update can be absorbed in logarithmic time.

9.2.1

Binary Indexed Trees

A binary indexed tree (or a Fenwick tree) is a dynamic variant of a prefix sum array. It provides two O(log n) time operations: a range sum query and a value update. Despite the name, the structure is usually represented as an array. We assume one-indexed arrays, which makes the implementation easier. Let p(k) denote the largest power of two that divides k. We store the tree as an array tree such that tree[k] = sumq(k − p(k) + 1, k): each position k contains the sum of a range of the original array of length p(k) ending at k.

Interactive structure

Follow the low bit

Each bar spans the array cells it covers. A query walks down by clearing the lowest set bit; an update walks up by adding it.

Two loops, both logarithmic

With a binary indexed tree, any sumq(1, k) takes O(log n) time, because a range [1, k] always divides into O(log n) subranges whose sums are stored in the tree. For example, to calculate sumq(1, 7), we divide the range [1, 7] into three subranges [1, 4], [5, 6], and [7, 7]. Since those sums are available in the tree, we can compute the entire range with the formula sumq(1, 7) = sumq(1, 4) + sumq(5, 6) + sumq(7, 7) = 16 + 7 + 4 = 27.

Then, to calculate sumq(a, b) where a > 1, the same trick as with prefix sum arrays applies: sumq(a, b) = sumq(1, b) − sumq(1, a − 1). Both terms take O(log n) time, so the total time is O(log n).

After an array value changes, several values in the binary indexed tree should be updated. For example, when the value at position 3 changes, the subranges [3, 3], [1, 4], and [1, 8] change. Since each array element belongs to O(log n) subranges, it suffices to update O(log n) tree values.

Example
array1 3 4 8 6 1 4 2
tree1 4 4 16 6 7 4 29

The query sumq(1, 7) reads the subranges [1, 4], [5, 6], and [7, 7]. The update at 3 changes [3, 3], [1, 4], and [1, 8].

Why k & −k isolates the lowest set bit

In two's complement, −k flips every bit of k and adds one. Every bit below the lowest set bit becomes zero, and that bit becomes one; all higher bits cancel when the two values are ANDed. The result is exactly the power of two that p(k) denotes.

This is also why the loop bounds are logarithmic: each iteration of the query removes one set bit, and a number below n has at most log2 n of them.

9.2.2

Segment Trees

A segment tree provides two O(log n) time operations: a range query and an update of an array value. Segment trees support sum queries, minimum queries, and many other queries. A segment tree is a binary tree whose bottom level nodes correspond to the array elements, and the other nodes contain information needed for range queries. We assume that the size of the array is a power of two and use zero-based indexing, which makes the tree convenient to build.

Interactive tree

The tree is stored in an array of 2n cells. The leaves occupy tree[n] … tree[2n − 1]; the parent of tree[k] is tree[⌊k/2⌋].

The array is [5, 8, 6, 3, 2, 7, 2, 6]. Internal nodes hold sums; leaves hold the values themselves. Cell 0 is unused.

Other queries

Segment trees support any range query where the range can be divided into two parts, each answered separately, and the answers combined efficiently. Examples are minimum and maximum, greatest common divisor, and the bit operations and, or, and xor.

The structure also allows a binary search style method for locating array elements. For example, if the tree supports minimum queries, we can find the position of the smallest value in O(log n) time.

Why the decomposition is short

When the sum is calculated from nodes located as high as possible, at most two nodes per level are needed. Hence, the total number of nodes is O(log n).

The bottom-up loop maintains a range in the segment tree array. Initially, the range is [a + n, b + n]. At each step the range moves one level higher, and the values of nodes outside the higher range are added to the sum.

9.2.3

Additional Techniques

A limitation of array-based data structures is that elements are indexed by consecutive integers. Difficulties arise when large indices are needed. Let us now consider an opposite situation, where we update ranges and retrieve single values.

Index compression

However, if we know all the indices needed during the algorithm beforehand, we can bypass the limitation with index compression. The idea is to replace the original indices with consecutive integers 0, 1, 2, and so on. We define a function c that compresses the indices.

The function gives each original index i a compressed index c(i) such that if a < b, then c(a) < c(b). After compression, a range [a, b] in the original array corresponds to the range [c(a), c(b)] in the compressed array.

The original array is the prefix sum of the difference array. A range update changes one difference cell at the start and one just past the end; a Fenwick or segment tree can then carry the difference array.

The advantage of the difference array is that we can update a range in the original array by changing just two elements in it. More precisely, to increase the values in range [a, b] by x, increase position a by x and decrease position b + 1 by x. Thus, we update single values and process sum queries in the difference array, so a binary indexed tree or segment tree applies.

Prefix sums remember every beginning. Sparse tables remember every power of two. Fenwick and segment trees remember just enough to repair themselves. A range query is never cheaper than the preprocessing that anticipates it.
