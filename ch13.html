13.1

Geometric Techniques

Make the special cases disappear before writing the geometry.

The hard part of computational geometry is rarely the mathematics. It is arranging the computation so that the number of special cases stays small and the implementation remains honest. This section builds a small kit of exact tools, then uses them on lines, segments, polygons and distances.

01

Represent

A point is a vector. Represent it as a complex number or a pair of coordinates.

02

Turn

A cross product signs the turn from one vector to another: left, straight or right.

03

Measure

Shoelace sums signed trapezoids. Pick counts lattice points when the vertices are integral.

04

Order

A sweep line sorts events by one coordinate and keeps only the active objects.

Prefer integer coordinates whenever the problem allows them: cross products and shoelace sums are then exact. Floating point is reserved for lengths and angles, where a square root is unavoidable.

Why exact arithmetic matters

A cross product of two integer vectors is an integer. Its sign is therefore reliable even when the value is enormous. If the same calculation is done in floating point, two points that should be exactly collinear can land on opposite sides of a line after rounding.

The book’s rule follows from this: use long long for coordinates when possible, and switch to long double only when the problem genuinely requires real lengths or angles.

13.1.1

A complex number x + yi is also a point and a vector. C++’s complex class supplies addition, length, angle and rotation, so the geometric code can stay short.

What conj does to a cross product

For a = (x1, y1) and b = (x2, y2), the complex product conj(a) * b has imaginary part x1y2 − x2y1, which is exactly the cross product. The real part is the dot product.

13.1.3

Polygon Area

The shoelace formula adds signed trapezoids between the polygon and a horizontal baseline. When every vertex is integral, Pick’s theorem reaches the same area by counting lattice points.

Interactive · two counts

The same 17/2, twice

Each edge contributes a signed trapezoid. The signs cancel the area outside the polygon.

½ |5 + 20 + 10 − 10 − 8| = 17/2
The sum is 17, so the area is 8.5. Walking the other way would negate every term, which is why the formula takes an absolute value.
positive trapezoid negative trapezoid

The five products walk the five edges in boundary order; the vertical edge has a zero-width trapezoid. Integer coordinates make every product exact.

Pick’s theorem

If every vertex has integer coordinates, the area is a + b/2 − 1, where a counts the lattice points strictly inside and b counts the lattice points on the boundary.

For this polygon, a = 6 and b = 7, so the area is 6 + 3.5 − 1 = 8.5. Count the boundary points with the gcd of each edge’s coordinate differences: an edge from (x1, y1) to (x2, y2) contains gcd(|x2−x1|, |y2−y1|) new lattice points.

Pick’s theorem needs integer vertices. It is a counting shortcut, not a replacement for shoelace on arbitrary real coordinates.

13.1.4

Distance Functions

Euclidean distance measures the straight line. Manhattan distance measures the walk along the axes. The second is often easier to optimize, especially after a 45° coordinate transform.

Interactive · two metrics

Same two points, two lengths

The Euclidean distance is the length of the difference vector: √((5−2)² + (2−1)²) = √10.

Both shapes contain exactly the points within distance one of the centre. Their corners and curves expose why the two metrics behave differently.

Why the transform preserves the distance

For p = (x1, y1) and q = (x2, y2), write p′ = (x1 + y1, y1 − x1) and similarly for q′. Then the two coordinate differences are (x1 − x2) + (y1 − y2) and (y1 − y2) − (x1 − x2). One of these has magnitude equal to |Δx| + |Δy|, and the other is no larger. Taking the maximum recovers the Manhattan distance.

13.2

Sweep Line Algorithms

Sort the plane by one coordinate and let a line do the work.

A sweep line turns geometry into a sequence of events. The line moves in one direction; at each event it updates a small active set and answers a local question. Three classic problems share this shape: intersections, closest pairs and convex hulls.

action sort events→ update active set→ query→ advance

The data structure is what makes the sweep fast. It holds only the objects the line currently touches, so each event costs a logarithmic update instead of a scan of the whole input.

13.2.1

Intersection Points

Five axis-aligned segments can be checked in ten pairs, but a sweep needs only eight events. Horizontal segments enter and leave an active set; each vertical segment asks how many active heights lie inside its span.

At a vertical segment between heights y1 and y2, count the active horizontal heights in that range. A binary indexed or segment tree answers the range count in O(log n), so all events take O(n log n) time.

Why event order matters at equal x

When several events share an x coordinate, process horizontal beginnings before vertical queries and horizontal endings after them. Otherwise a vertical segment can miss a horizontal one that starts at the same x, or count one that ends there.

13.2.2

Closest Pair Problem

Scan the points from left to right while keeping the smallest distance d seen so far. Only points in a narrow strip behind the sweep line can improve it — and that strip contains only a constant number of points.

Why the strip is small

Suppose the current minimum is d. Divide the strip into boxes of size d/2 by d/2. If one box contained two points, those two points would be closer than d, contradicting the definition of d. The strip is therefore sparse.

What the algorithm stores

Keep the points whose x coordinate lies in [x − d, x], ordered by y. For each new point, inspect only the neighbours within d in that order. A balanced tree gives O(log n) per point and O(n log n) overall.

13.2.3

Convex Hull Problem

The convex hull is the smallest convex polygon containing every point. Andrew’s algorithm sorts the points, builds the upper hull, then mirrors the same pass for the lower hull.

The check is a cross product: while the last three hull points make a left turn, remove the middle one. After both passes, the hull contains each extreme point once, in counterclockwise order. Sorting dominates the running time, so the algorithm is O(n log n).

Collinear points and duplicate points

Andrew’s algorithm removes collinear points when the turn test uses ≥ 0 rather than > 0. This leaves only the extreme vertices. If the input can contain duplicates, remove them after sorting; otherwise the same point can appear twice on the hull.
