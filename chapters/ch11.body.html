11.1

Number Theory

Number theory is the study of the integers. In a contest it is usually four operations: deciding what divides what, filtering the primes, taking a greatest common divisor, and doing all of it modulo m.

Number theory studies the integers. In this section we discuss a selection of number-theoretical topics and algorithms, such as finding primes and factors, and solving integer equations.

Divisibility

An integer a is a factor, or divisor, of an integer b if a divides b. If a is a factor of b, we write a | b, otherwise a ∤ b. For example, the factors of 24 are 1, 2, 3, 4, 6, 8, 12, and 24.

Primality

An integer n > 1 is a prime if its only positive factors are 1 and n. For example, 7, 19, and 41 are primes, but 35 is not, because 5 · 7 = 35.

Factorisation

Every integer n > 1 has a unique prime factorization n = p1α1p2α2 ⋯ pkαk, where p1, p2, …, pk are distinct primes and α1, α2, …, αk are positive integers. For example, 84 = 22 · 31 · 71.

11.1.1

Primes and Factors

Let τ(n) denote the number of factors of n. For example, τ(12) = 6, because the factors of 12 are 1, 2, 3, 4, 6, and 12. Let σ(n) denote the sum of factors of n. For example, σ(12) = 28, because 1 + 2 + 3 + 4 + 6 + 12 = 28. To calculate them, we use the formulas below.

number of factors τ(n) = ∏i=1k (αi + 1)
sum of factors σ(n) = ∏i=1k (1 + pi + ⋯ + piαi) = ∏i=1k piαi+1 − 1pi − 1

If n is not prime, it can be represented as a product a · b, where a ≤ √n or b ≤ √n, so it certainly has a factor between 2 and ⌊√n⌋. Using this observation, we can both test whether n is prime and find its prime factorization in O(√n) time. The following function constructs a vector that contains the prime factorization of n. It divides n by its prime factors and adds them to the vector.

There are infinitely many primes

It is easy to show that there is an infinite number of primes. If there were finitely many, we could construct a set P = {p1, p2, …, pn} containing all of them. Using such a set, we could form a new prime p1p2 ⋯ pn + 1 larger than every element of P. This is a contradiction, and the number of primes has to be infinite.

The prime-counting function π(n) gives the number of primes up to n. For example, π(10) = 4, because the primes up to 10 are 2, 3, 5, and 7. One can show that π(n) ≈ n / ln n, so primes are quite frequent.

Why αi + 1 choices

For each prime pi, there are αi + 1 ways to choose how many times it appears. The choices are independent, so the counts multiply. The sum formula applies the same product to the geometric series 1 + p + ⋯ + pα.

11.1.2

Sieve of Eratosthenes

The sieve of Eratosthenes is a preprocessing algorithm that constructs an array sieve for checking efficiently whether any integer x between 2 … n is prime. If x is prime, sieve[x] = 0; otherwise sieve[x] = 1. To construct the array, the algorithm iterates through the integers 2 … n one by one. Whenever a new prime x is found, it records that 2x, 3x, 4x, etc., are not primes.

11.1.3

Euclid’s Algorithm

The greatest common divisor of integers a and b, denoted gcd(a, b), is the largest integer that divides both. For example, gcd(30, 12) = 6. The lowest common multiple, denoted lcm(a, b), is the smallest integer divisible by both a and b. The formula

lcm(a, b) = abgcd(a, b) lcm(30, 12) = 360 / 6 = 60

One way to find gcd(a, b) is to factor a and b into primes, then choose for each prime the largest power that appears in both factorizations. However, this is not efficient if a and b are large. Euclid’s algorithm calculates gcd(a, b) efficiently. It is based on the formula

gcd(a, b) = aif b = 0gcd(b, a mod b)if b ≠ 0

Euclid’s algorithm works in O(log n) time, where n = min(a, b). It can also be extended to give integers x and y for which ax + by = gcd(a, b). For example, when a = 30 and b = 12, 30 · 1 + 12 · (−2) = 6.

11.1.4

Modular Exponentiation

We often need to calculate xn mod m efficiently. This can be done in O(log n) time using the following recursive formula:

xn = 1n = 0xn/2 · xn/2n evenxn−1 · xn odd

For example, to calculate x100, we first calculate x50 and then use x100 = x50 · x50. To calculate x50, we first calculate x25, and so on. Since n halves whenever it is even, the calculation takes O(log n) time.

11.1.5

Euler’s Theorem

Two integers a and b are coprime if gcd(a, b) = 1. Euler’s totient function φ(n) gives the number of integers between 1 … n that are coprime to n. For example, φ(10) = 4, because 1, 3, 7, and 9 are coprime to 10.

Any value of φ(n) can be calculated from the prime factorization of n using the formula

φ(n) = ∏i=1k piαi−1(pi − 1)

For example, since 10 = 2 · 5, φ(10) = 20 · (2 − 1) · 50 · (5 − 1) = 4. For 12 = 22 · 3, it gives 21(2 − 1) · 30(3 − 1) = 4.

If m is prime, φ(m) = m − 1.

Euler’s theorem: if x and m are coprime, then xφ(m) mod m = 1.

For example, Euler’s theorem tells us that 74 mod 10 = 1, because 7 and 10 are coprime and φ(10) = 4. If m is prime, φ(m) = m − 1, so the formula becomes xm−1 mod m = 1, known as Fermat’s little theorem. This also implies xn mod m = xn mod (m−1) mod m, which lets us calculate xn when n is very large.

Modular multiplicative inverse

The modular multiplicative inverse of x with respect to m is a value invm(x) such that x · invm(x) mod m = 1. It exists exactly when x and m are coprime, and can then be calculated using the formula

invm(x) = xφ(m)−1 mod m

In particular, if m is prime, φ(m) = m − 1 and the formula becomes xm−2 mod m. Modular inverses let us divide modulo m, because division by x is multiplication by invm(x). For example, since inv17(6) = 3, we can calculate 36/6 mod 17 as 36 · 3 mod 17.

Where the exponent reduction comes from

Write n = q(m−1) + r. Then xn = (xm−1)q · xr. Fermat’s theorem makes the first factor 1 modulo the prime m, leaving xr.

11.1.6

Solving Equations

A Diophantine equation has the form ax + by = c, where a, b, and c are constants and x and y are the unknowns. Each number in the equation has to be an integer. For example, one solution to 5x + 2y = 11 is x = 3 and y = −2. We can solve a Diophantine equation efficiently using the extended Euclid’s algorithm, which gives integers x and y satisfying ax + by = gcd(a, b). The equation can be solved exactly when c is divisible by gcd(a, b).

A worked equation

As an example, let us find integers x and y that satisfy 39x + 15y = 12. The equation can be solved, because gcd(39, 15) = 3 and 3 | 12. The extended Euclid’s algorithm gives 39 · 2 + 15 · (−5) = 3, and multiplying by 4 gives 39 · 8 + 15 · (−20) = 12, so x = 8 and y = −20.

where g = gcd(a, b) and k is any integer.

11.2

Combinatorics

Combinatorics counts combinations without generating them. The whole subject is a set of shortcuts for a question that would otherwise need a list.

Combinatorics studies methods for counting combinations of objects. Usually the goal is to count them efficiently without generating each combination separately. In this section we discuss combinatorial techniques that apply to a large number of problems.

11.2.1

Binomial Coefficients

The binomial coefficient C(n, k) gives the number of ways to choose a subset of k elements from a set of n elements. For example, C(5, 3) = 10, because {1, 2, 3, 4, 5} has 10 subsets of 3 elements:

C(5, 3) = 10
{1,2,3}{1,2,4}{1,2,5}{1,3,4}{1,3,5}{1,4,5}{2,3,4}{2,3,5}{2,4,5}{3,4,5}
Recursion (nk) = (n−1k−1) + (n−1k)

If we include x in our subset, we must choose k − 1 elements from the remaining n − 1. If we do not include x, we choose k elements from n − 1.

Factorials (nk) = n!k!(n−k)!

There are n! permutations of n elements. We go through all permutations, include the first k elements in the subset, and since order inside and outside the subset does not matter, divide by k! and (n−k)!.

Symmetry and sum (nk) = (nn−k)
Σk=0n (nk) = 2n

We actually divide a set of n elements into two subsets: the first contains k elements and the second contains n−k elements. The sum of binomial coefficients is 2n.

11.2.2

Catalan Numbers

The Catalan number Cn gives the number of valid parenthesis expressions with n left and n right parentheses. For example, C3 = 5, because there are five such expressions using three of each:

Recurrence
Cn = Σi=0n−1 Ci Cn−i−1

We divide the expression into two parts that are both valid, with the first part as short as possible but not empty. For each i, the first part contains i+1 pairs and the number of valid expressions is Ci Cn−i−1. The base case is C0 = 1, the empty expression with zero pairs.

Closed form
Cn = 1n+1 (2nn)

There are C(2n, n) ways to construct a (not necessarily valid) expression with n left and n right parentheses. A nonvalid expression contains a prefix where right parentheses outnumber left. Pick the shortest such prefix and reverse each parenthesis in it. The result has n+1 left and n−1 right parentheses, and there are C(2n, n+1) such expressions, which equals the number of nonvalid ones.

Catalan numbers also count certain tree structures. First, Cn equals the number of binary trees of n nodes when left and right children are distinguished. For example, since C3 = 5, there are 5 binary trees of 3 nodes. Then, Cn also equals the number of general rooted trees of n+1 nodes; for example, there are 5 rooted trees of 4 nodes.

11.2.3

Inclusion–Exclusion

Inclusion-exclusion counts the size of a union of sets when the sizes of the intersections are known, and vice versa. A simple example is the formula

|A ∪ B| = |A| + |B| − |A ∩ B|

Counting derangements

As an example, let us count the derangements of {1, 2, …, n}: permutations where no element remains in its original place. When n = 3, there are two: (2, 3, 1) and (3, 1, 2). One approach is inclusion-exclusion. Let Xk be the set of permutations with element k at position k. The number of derangements equals n! − |X1 ∪ X2 ∪ ⋯ ∪ Xn|.

11.2.4

Burnside’s Lemma

Burnside’s lemma counts distinct combinations so that symmetric ones are counted only once. It states that the number of combinations is

1n Σk=1n c(k)

Here there are n ways to change the position of a combination, and c(k) combinations remain unchanged when the kth way is applied. As an example, let us count the necklaces of n pearls, each with m possible colors. Two necklaces are symmetric if they are similar after rotation. There are n ways to change a necklace’s position, because it can be rotated k = 0, 1, …, n−1 steps clockwise. A total of mgcd(k,n) necklaces remain the same, because blocks of pearls of size gcd(k, n) replace each other. Thus, by Burnside’s lemma, the number of distinct necklaces is

1n Σk=0n−1 mgcd(k,n)

For example, the number of distinct necklaces of 4 pearls and 3 colors is (34 + 3 + 32 + 3) / 4 = 24.

11.2.5

Cayley’s Formula

Cayley’s formula states that there are nn−2 distinct labeled trees of n nodes. The nodes are labeled 1, 2, …, n, and two trees are distinct if their structure or labeling differs. For example, when n = 4, there are 44−2 = 16 labeled trees. The formula can be proved using Prüfer codes.

The code is constructed by a process that removes n−2 leaves from the tree. At each step, the leaf with the smallest label is removed, and the label of its only neighbor is added to the code. For example, the Prüfer code of the tree above is [4, 4, 2], because we remove leaves 1, 3, and 4.

Every tree has a Prüfer code, and more importantly, the original tree can be reconstructed from it. Hence the number of labeled trees of n nodes equals nn−2, the number of Prüfer codes of length n.

11.3

Matrices

A matrix is a two-dimensional array with arithmetic. Its real power in a contest is compression: one multiplication can advance a whole recurrence by one step.

A matrix corresponds to a two-dimensional array in programming. A matrix of size a × b has a rows and b columns. The notation A[i, j] refers to the element in row i and column j. A special case is a vector, a one-dimensional matrix of size n × 1. A square matrix has the same number of rows and columns.

The transpose AT of a matrix A is obtained by swapping rows and columns, i.e., AT[i, j] = A[j, i].

11.3.1

Matrix Operations

The sum A + B is defined if A and B have the same size. The result is a matrix whose elements are the sums of the corresponding elements. Multiplying A by a value x multiplies each element of A by x. The product AB is defined if A is a × n and B is n × b, i.e., the width of A equals the height of B. The result is an a × b matrix whose elements are calculated by the formula

AB[i, j] = Σk=1n A[i, k] · B[k, j]

Associative, not commutative

Matrix multiplication is associative, so A(BC) = (AB)C, but not commutative, so usually AB ≠ BA.

An identity matrix is a square matrix with 1 on the diagonal and 0 elsewhere. Multiplying by it does not change a matrix: AI = IA = A.

11.3.2

Linear Recurrences

A linear recurrence is a function f(n) with initial values f(0), f(1), …, f(k−1) whose larger values are calculated recursively by

f(n) = c1f(n−1) + c2f(n−2) + ⋯ + ckf(n−k)

Dynamic programming calculates any f(n) in O(kn) time by computing f(0), f(1), …, f(n) one after another. We can also calculate f(n) in O(k3 log n) time using matrix operations. This is an important improvement if k is small and n is large.

Fibonacci numbers

A simple example is the Fibonacci recurrence: f(0) = 0, f(1) = 1, and f(n) = f(n−1) + f(n−2). Here k = 2 and c1 = c2 = 1. To calculate Fibonacci numbers efficiently, we represent the formula as a 2 × 2 square matrix X for which X · [f(i), f(i+1)]T = [f(i+1), f(i+2)]T. It turns out that such a matrix is

X = 0111

Thus f(i) and f(i+1) are the “input” for X, which calculates f(i+1) and f(i+2). Thus we can calculate f(n) using the formula

[f(n), f(n+1)]T = Xn · [0, 1]T

Since Xn can be calculated in O(log n) time, so can f(n).

The general case

Let us now consider the general case, where f(n) is any linear recurrence. Again, our goal is a matrix X for which X · [f(i), f(i+1), …, f(i+k−1)]T = [f(i+1), f(i+2), …, f(i+k)]T. Such a matrix is

X = 010000100001ckck−1ck−2c1

In the first k−1 rows, each element is 0 except one 1. These rows replace f(i) with f(i+1), f(i+1) with f(i+2), and so on. The last row contains the recurrence coefficients for the new value f(i+k). Now f(n) can be calculated in O(k3 log n) time.

11.3.3

Graphs and Matrices

Powers of adjacency matrices have interesting properties. When M is the adjacency matrix of an unweighted graph, Mn gives, for each node pair (a, b), the number of paths from a to b with exactly n edges. A node may appear on a path several times.

Weighted graphs

In a weighted graph, a similar idea gives, for each node pair (a, b), the shortest length of a path from a to b with exactly n edges. Instead of the usual matrix product, we take minima instead of sums and sums instead of products:

AB[i, j] = mink (A[i, k] + B[k, j])

After this modification, matrix powers minimize path lengths. For example, the minimum length of a 4-edge path from node 2 to node 5 is 8; such a path is 2 → 1 → 4 → 2 → 5.

Gaussian Elimination

Gaussian elimination systematically solves a group of linear equations. The idea is to represent the equations as a matrix and apply simple row operations that preserve the information and determine each variable. We use three types: swap two rows, multiply a row by a nonnegative constant, and add a row multiplied by a constant to another row. Each operation preserves the equations, so the final solution agrees with the original. To solve them, we transform the matrix so that the last column reads x1 = c1, x2 = c2, …, xn = cn.

11.4

Probability

A probability is a number between 0 and 1. The work is in finding the right sample space, not in the arithmetic.

To calculate the probability of an event, we can either use combinatorics or simulate the process that generates the event.

Three cards, one value

As an example, consider an experiment where we draw the three top cards from a shuffled deck. What is the probability that each card has the same value? One way is to use the formula number of desired outcomes / total number of outcomes. The desired outcomes are those in which the value of each card is the same. There are 13 C(4,3) such outcomes, because there are 13 possible values and C(4,3) ways to choose 3 suits from 4. There are C(52,3) outcomes in total, because we choose 3 cards from 52.

13 · C(4,3)C(52,3) = 1425

11.4.1

Working with Events

A convenient way to represent events is with sets. For example, the possible outcomes when throwing a die are {1, 2, 3, 4, 5, 6}, and any subset is an event. The event “the outcome is even” is the set A = {2, 4, 6}. Each outcome x has a probability p(x), and P(A) is the sum of the probabilities of its outcomes.

complementP(Ā) = 1 − P(A)

At least one six in ten throws: 1 − (5/6)10.

unionP(A ∪ B) = P(A) + P(B) − P(A ∩ B)

If A and B are disjoint, i.e., A ∩ B is empty, then P(A ∪ B) = P(A) + P(B).

intersectionP(A ∩ B) = P(A)P(B | A)

Events A and B are independent if P(A|B) = P(A) and P(B|A) = P(B). Then P(A ∩ B) = P(A)P(B).

11.4.2

Random Variables

A random variable is a value generated by a random process. For example, when throwing two dice, a possible random variable is X = “the sum of the outcomes”. We denote by P(X = x) the probability that X takes the value x. For example, P(X = 10) = 3/36, because there are 36 outcomes and three ways to obtain 10: [4, 6], [5, 5], and [6, 4]. The expected value E[X] is the average value of X, calculated as a sum

E[X] = Σx P(X = x) · x

Empty boxes

Let us now consider n balls placed randomly in n boxes, and calculate the expected number of empty boxes. Each ball is equally likely to land in any box. For example, when n = 2, the possibilities give 0, 0, 1, and 1 empty boxes, so the expected number is (0 + 0 + 1 + 1)/4 = 1/2.

In the general case, the probability that a single box is empty is ((n−1)/n)n, because no ball may be placed in it. By linearity, the expected number of empty boxes is

11.4.3

Markov Chains

A Markov chain is a random process consisting of states and transitions between them. For each state, we know the probabilities of moving to other states. It can be represented as a graph whose nodes are states and whose edges are transitions. As an example, consider an n-floor building where we start on floor 1. At each step, we walk either one floor up or one floor down, except that we always walk up from floor 1 and down from floor n. What is the probability of being on floor m after k steps? For n = 5, each floor corresponds to a state in a Markov chain.

The probability distribution of a Markov chain is a vector [p1, p2, …, pn], where pk is the probability that the current state is k. The sum p1 + p2 + ⋯ + pn = 1 always holds. In the scenario above, the initial distribution is [1, 0, 0, 0, 0], because we begin on floor 1. The next is [0, 1, 0, 0, 0], because we can only move to floor 2. Then we can move one floor up or down, so the next distribution is [1/2, 0, 1/2, 0, 0], and so on.

An efficient way to simulate the walk is dynamic programming. The idea is to maintain the probability distribution, and at each step go through all possible moves. This simulates m steps in O(n2m) time. The transitions can also be a matrix that updates the distribution; calculating matrix powers efficiently gives the distribution after m steps in O(n3 log m) time.

11.4.4

Randomized Algorithms

Sometimes randomness solves a problem even when the problem is not about probabilities. A randomized algorithm is based on randomness. There are two popular types:

Monte Carlo

Order statistics

The kth order statistic of an array is the element at position k after sorting in increasing order. Any order statistic is easy to calculate in O(n log n) time by sorting, but is it really needed to sort the entire array just to find one element? We can find order statistics with a Las Vegas algorithm whose expected running time is O(n). It chooses a random element x and moves elements smaller than x to the left part of the array, and all others to the right part. This takes O(n) time with n elements. Assume the left part contains a elements and the right part b elements. If a = k, x is the kth order statistic. If a > k, we recursively find the kth order statistic in the left part; if a < k, we find the rth order statistic in the right part, where r = k − a − 1. When x is chosen randomly, the array about halves at each step, so the time complexity is about n + n/2 + n/4 + n/8 + ⋯ = O(n). The worst case requires O(n2) time, if x is always chosen as one of the smallest or largest elements and O(n) steps are needed. However, the probability of this is so small that we may assume it never happens in practice.

02

Verifying a matrix product

Given n × n matrices A, B, and C, our next problem is to verify whether AB = C. We can of course calculate AB in O(n3) time, but one could hope that verifying the answer is easier than calculating it from scratch. A Monte Carlo algorithm solves the problem in only O(n2) time. The idea is simple: choose a random vector X of n elements and calculate ABX and CX. If ABX = CX, we report AB = C; otherwise AB ≠ C. The time complexity is O(n2), because both products take O(n2) time. We calculate ABX efficiently as A(BX), so only two multiplications of n × n and n × 1 matrices are needed. The drawback is the small chance of a mistake when reporting AB = C. In practice that probability is small, and we can decrease it by verifying with multiple random vectors X before reporting AB = C.

03

Graph colouring

Given a graph with n nodes and m edges, find a two-coloring so that at least m/2 edges have endpoints of different colors. A Las Vegas algorithm generates random colorings until a valid one is found. In a random coloring, each node’s color is chosen independently, with probability 1/2 for each color. Hence the expected number of edges with different-colored endpoints is m/2, so a valid coloring appears quickly in practice.

11.5

Game Theory

Two players, alternating moves, no randomness, complete information. A position is winning if some move hands the opponent a losing position; otherwise it is losing.

We focus on two-player games where the players move alternately, have the same set of moves, and face no randomness. Our goal is a strategy that wins no matter what the opponent does, if such a strategy exists. It turns out that there is a general strategy for such games, and we can analyze them using nim theory.

11.5.1

Game States

Consider a game that starts with a heap of n sticks. Two players move alternately, and each move removes 1, 2, or 3 sticks. The player who removes the last stick wins. The game consists of states 0, 1, 2, …, n, where the state number is the number of sticks left. State 0 is clearly losing, because the player cannot move. States 1, 2, and 3 are winning, because the player can remove 1, 2, or 3 sticks and win. State 4, in turn, is losing, because any move leads to a winning state for the opponent.

A divisibility game

Let us consider another stick game, where in state k we may remove any number x of sticks such that x is smaller than k and divides k. For example, in state 8 we may remove 1, 2, or 4 sticks, but in state 7 the only move is to remove 1. The final state is always state 1, which is losing, because there are no valid moves. It turns out that all even states are winning and all odd states are losing.

Why? An even state can remove 1 to reach an odd state; every move from an odd state removes an odd divisor (since all divisors of an odd number are odd) and therefore lands on an even state. Induction from 1 finishes the argument.

11.5.2

Nim Game

There are n heaps in nim, each containing some number of sticks. The players move alternately; on each turn, a player chooses a nonempty heap and removes any number of sticks from it. The winner removes the last stick. The states are [x1, x2, …, xn], where xi is the number of sticks in heap i. For example, [10, 12, 5] has three heaps of 10, 12, and 5 sticks. The state [0, 0, …, 0] is losing, because no sticks can be removed, and it is always the final state.

It turns out that we can easily classify any nim state by calculating the nim sum

s = x1 ⊕ x2 ⊕ ⋯ ⊕ xn

States with nim sum 0 are losing; all others are winning. For example, the nim sum of [10, 12, 5] is 10 ⊕ 12 ⊕ 5 = 3, so the state is winning. The final state [0, 0, …, 0] is losing, and its nim sum is 0, as expected. From any other losing state, any move leads to a winning state, because changing a single xi changes the nim sum, so it is nonzero after the move.

We can move to a losing state if some heap i has xi ⊕ s < xi. Then we remove sticks from heap i until it contains xi ⊕ s, which leads to a losing state. There is always such a heap: one where xi has a one bit at the position of the leftmost one bit of s.

Misère nim

In a misère nim game, the goal is opposite: the player who removes the last stick loses. It turns out that the game can be played almost like standard nim. Play it like the standard game, but change strategy at the end, in a situation where each heap would contain at most one stick after the next move. In the standard game, we choose a move that leaves an even number of one-stick heaps. In misère nim, we leave an odd number. This works because such a state always appears, and it is winning, since it contains exactly one heap with more than one stick, so the nim sum is not 0.

11.5.3

Sprague–Grundy Theorem

The Sprague–Grundy theorem generalizes the nim strategy to all games that fulfill these requirements: two players move alternately; the possible moves in a state do not depend on whose turn it is; the game ends when a player cannot move; it surely ends sooner or later; the players have complete information about states and moves; and there is no randomness.

The mex rule

The idea is to calculate for each state a Grundy number corresponding to the number of sticks in a nim heap. Knowing all Grundy numbers, we can play the game like nim. The Grundy number of a state is calculated by

g = mex({g1, g2, …, gn})

where g1, g2, …, gn are the Grundy numbers of the states reachable from it, and mex gives the smallest nonnegative number not in the set. For example, mex({0, 1, 3}) = 2. A state with no possible moves has Grundy number 0, because mex(∅) = 0. A losing state has Grundy number 0, and a winning state has a positive Grundy number.

Assume the game consists of subgames, and on each turn the player chooses a subgame and then a move in it. The game ends when no subgame has a move. Then the Grundy number of the whole game equals the nim sum of the subgames’ Grundy numbers.

The theorem asks for
  • two players
  • alternating moves
  • same moves for both
  • no randomness
  • complete information
  • guaranteed end

A state with Grundy number x corresponds to a nim heap of x sticks. In particular, if x > 0, we can move to states with Grundy numbers 0, 1, …, x − 1. One difference: we may be able to move to a state whose Grundy number is larger than x, “adding” sticks to a heap. The opponent can always cancel such a move, so the strategy does not change.

As an example, consider a game with three mazes. On each turn, the player chooses a maze and moves the figure in it. Here the nim sum of the Grundy numbers is 2 ⊕ 3 ⊕ 3 = 2, so the first player can win. One optimal move is two steps up in the first maze, producing the nim sum 0 ⊕ 3 ⊕ 3 = 0.

Primes, binomial coefficients, matrix powers, distributions, and Grundy numbers are all compressions: each one replaces a large explicit object with a small invariant that is enough to answer the question.
