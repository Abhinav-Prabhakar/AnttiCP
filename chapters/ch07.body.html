7.1

Basics of Graphs

A graph is a set of nodes, a set of edges, and a question about how they connect.

The same picture can be a road network, a dependency list, a state machine, or a set of friendships. What changes is the question: what is reachable, what is the shortest route, and which edges hold everything together.

7.1.1Graph Terminology

Path

A sequence of edges from one node to another. Length is the number of edges.

Cycle

A path whose first and last node are the same.

Connected

There is a path between every pair of nodes. The connected parts are the components.

Tree

A connected graph with no cycle. On c nodes it has exactly c − 1 edges.

Directed

Every edge can be traversed one way only. A node has an indegree and an outdegree.

Weighted

Every edge carries a weight. The length of a path is the sum of its weights.

Neighbours

Two nodes are adjacent if an edge joins them. The degree counts the neighbours.

Bipartite

The nodes can be split into two sides so that every edge crosses. Equivalently, there is no odd cycle.

Two facts worth keeping

The degrees of a graph always sum to 2m: every edge raises the degree of both endpoints by one. So the sum is even, and the number of odd-degree nodes is even too.

A graph is regular if every node has the same degree d, and complete if every node is adjacent to every other, so every degree is n − 1. In a directed graph, the indegree counts edges arriving and the outdegree counts edges leaving; their totals are both m.

      7.2
      
Graph Traversal

    


    
Both traversals visit everything reachable. The difference is the order — and the order is the algorithm.

    
Depth-first search commits to a path; breadth-first search expands in rings. Both run in O(n + m) time and both are built on the same three ingredients: adjacency lists, a visited array, and a way to remember what comes next.


    
7.2.1Depth-First Search


    
Depth-first search follows a single path as long as it keeps finding new nodes. At each node it picks an unvisited neighbour and recurses; when there is nothing left to explore, it returns to the previous node and tries the next branch. The visited array guarantees that every node and every edge is processed once, so the running time is O(n + m).


    

      

        

        

          
          
        

      

      

      

    


    
7.2.2Breadth-First Search


    
Breadth-first search moves in layers: first the start node, then every node at distance 1, then distance 2, and so on. A FIFO queue holds the frontier. When a node is taken from the front, each unvisited neighbour is marked and pushed to the back with distance one greater. The first time a node is reached is therefore along a shortest path — in an unweighted graph, where every edge costs the same.

7.2.3Applications


    

      

        01
        
Connectivity

        
Run a traversal from any node. If every node is reached, the graph is connected. Otherwise restart at each unvisited node: every restart discovers one new component.

      

      

        02
        
Cycle detection

        
During a traversal, an edge to an already visited node that is not the node we came from closes a cycle. Equivalently, a component with c nodes and at least c edges must contain a cycle.

      

      

        03
        
Bipartiteness

        
Colour the start node X, its neighbours Y, their neighbours X, and so on. If two adjacent nodes ever get the same colour, the graph is not bipartite.

      

    


    

    

      Why two colours are easy and three are not
      

        
Once the first node of a component is coloured, the colour of every other node in that component is forced: each edge flips it. There is no choice left to make, which is why the traversal decides bipartiteness in linear time.

        
With three colours the problem changes character. Deciding whether a graph can be coloured with k colours is NP-hard already for k = 3; no traversal-style algorithm is known.

      

    

  







  

    

      7.3
      
Shortest Paths

    


    
Weights turn a graph into a cost model. The shortest path is the cheapest way through, not necessarily the one with the fewest edges.

    
In an unweighted graph, BFS already finds shortest paths. With weights, the problem needs more care: a light edge can be a detour, and a heavy edge can be the only way forward.


    
7.3.1Bellman–Ford Algorithm


    
Bellman–Ford is the patient version. It keeps a distance array — 0 at the source, infinity everywhere else — and sweeps the entire edge list n − 1 times. On each sweep, every edge (a, b, w) offers the candidate distance[a] + w to b. A shortest path can contain at most n − 1 edges, so after n − 1 sweeps every distance is final. The cost is O(nm).


    

    
One more sweep is a negative-cycle test. If any distance still improves after n − 1 rounds, the graph contains a cycle of negative total weight: walking around it makes the path cheaper forever, so a shortest path does not exist. The test works from any starting node, because a negative cycle eventually affects a reachable distance — or reveals itself in the component it belongs to.


    
7.3.2Dijkstra’s Algorithm


    
Dijkstra’s algorithm is the greedy version, and it is faster when every edge weight is non-negative. It repeatedly settles the unprocessed node with the smallest known distance, then relaxes every edge leaving that node. A priority queue holds the candidates; in the standard competitive-programming implementation a node is pushed again whenever its distance improves, and stale entries are skipped. Each edge is used once, so the running time is O(n + m log m).


    

      Why the greedy step is safe
      
When the smallest tentative distance is d, no route through an unsettled node can be shorter: every edge is non-negative, so any detour only adds to d. The node can be settled, and its distance will never change again.

      
    


    

      

        
Bellman–Ford can afford negative edges because it keeps revising; Dijkstra cannot. In the graph below the shortest route from 1 to 4 is 1 → 3 → 4, of length 1. Dijkstra settles node 2 at distance 2 first, relaxes 2 → 4 to 5, and never reconsiders node 4 after the negative edge becomes available.

        
This is not a bug to patch: it is the assumption that makes the algorithm fast. If negative edges are present, use Bellman–Ford, or reweight the graph when the structure allows it.

      

      
    


    
7.3.3Floyd–Warshall Algorithm


    
Floyd–Warshall answers all pairs at once. It starts from the adjacency matrix — 0 on the diagonal, the edge weight where an edge exists, infinity elsewhere — and admits nodes as intermediate stops one at a time. When node k becomes allowed, every pair (i, j) is offered the route i → k → j. After n rounds the matrix holds every shortest distance. Three nested loops give O(n3), so the method is reserved for graphs small enough to afford it.


    

    
the updatedist[i][j] ← min(dist[i][j], dist[i][k] + dist[k][j])for every k, then every i, then every j

  







  

    

      7.4
      
Directed Acyclic Graphs

    


    
A directed acyclic graph has a direction and no way back. That single restriction makes ordering — and dynamic programming — possible.

    
Many problems become easier when the dependencies form a DAG: courses before prerequisites, tasks before deadlines, states before transitions. A DAG always has a topological order, and a topological order turns a graph DP into an array DP.


    
7.4.1Topological Sorting


    
A topological sort lists the nodes so that every edge points forward: if there is a path from a to b, then a appears before b. Such an order exists exactly when the graph is acyclic. If a cycle exists, no node of the cycle can come before the others, and no order can satisfy every edge.


    
DFS constructs the order with three states: 0 for unprocessed, 1 for in progress, 2 for finished. A node enters state 1 when the search arrives and state 2 after all its outgoing edges are done. Appending nodes in finish order and reversing the list puts every node before its descendants. An edge to a node still in state 1 closes a cycle, and the graph has no topological sort.


    

    

      Cycle found during the search
      

        
If a DFS edge leads to a node whose state is 1, the search has returned to a node on its own current path. That closes a cycle, so no topological order exists. This is the cheapest way to test whether a directed graph is acyclic; the same traversal that would build the order reports the failure.

      

    


    
7.4.2Dynamic Programming


    
Once the nodes are in topological order, a DP over the graph is just a DP over an array. Let paths(x) be the number of routes from a fixed start a to x. The base case is paths(a) = 1, and every other value is the sum over the nodes with an edge into x. Topological order guarantees those predecessors are already computed.


    

    

      The four routes from 1 to 6
      

        

          1 → 2 → 3 → 6
          1 → 2 → 6
          1 → 4 → 5 → 2 → 3 → 6
          1 → 4 → 5 → 2 → 6
        

        
Counting paths is only well-defined because the graph is acyclic. In a graph with a cycle, a single walk could be extended by going around the cycle any number of times.

      

    


    
The same translation works for many problems: shortest and longest paths, the fewest or most edges, and even the coin problem from Chapter 6. There, each node is a sum of money and each edge is a coin; the shortest path from 0 to n uses the fewest coins, and the number of paths counts the solutions. When a graph is not acyclic, Dijkstra can first build the shortest-path graph — keep only the edges that lie on a shortest route — and that graph is a DAG.

  







  

    

      7.5
      
Successor Graphs

    


    
A successor graph gives every node exactly one outgoing edge. Each component is a single cycle with paths feeding into it.

    
Successor graphs — also called functional graphs — are the shape of a function iterated on itself. They appear in simulations, in “follow the pointer” problems, and wherever a state has exactly one next state.

7.5.1Finding Successors


    
Walking k steps one at a time costs O(k). Binary lifting precomputes the answer for every power of two, using the recurrence succ(x, 2k) = succ(succ(x, k), k). Any step count is a sum of powers of two, so a query becomes O(log k) jumps after O(n log u) preprocessing, where u is the largest number of steps ever requested.


    

    
7.5.2Cycle Detection


    
A graph that is one path ending in a cycle has two natural questions: which node is the first on the cycle, and how long is the cycle? Walking while remembering every visited node answers both in O(n) time and O(n) memory. Floyd’s algorithm gets the same time with O(1) memory by using two pointers.


    

      

        
Start both pointers at the start node. On every turn, a walks one step and b walks two. If the path ends in a cycle they eventually meet. At that moment a has walked k steps and b has walked 2k, so the cycle length divides k.

        
To find the first cycle node, put a back at the start and advance both pointers one step at a time. They meet exactly at the entrance. Then walk b around the cycle until it returns to a to measure the length.

        

          1 a ← succ(a), b ← succ(succ(b))
          2 repeat until a = b
          3 a ← start; advance both until a = b
          4 count steps from a back to a
        

      

      
    

  







  

    

      7.6
      
Minimum Spanning Trees

    


    
A spanning tree keeps every node and just enough edges to connect them. The minimum spanning tree is the cheapest such skeleton.

    
A spanning tree has n − 1 edges, is connected, and has no cycle. Its weight is the sum of its edge weights. A graph may have many spanning trees — and several minimum ones — but every minimum spanning tree has the same weight.

7.6.1Kruskal’s Algorithm


    
Kruskal sorts the edges by weight and walks the list. An edge is added when its endpoints are in different components; otherwise it would close a cycle and is skipped. After n − 1 additions the tree is complete. The only query the algorithm needs is “are these two nodes in the same component?” — and the structure that answers it is union-find.

      Why the greedy choice is safe
      

        
Let e be the lightest edge of the graph. If a minimum spanning tree does not contain e, add e to it: this creates a cycle, and some other edge f on that cycle can be removed. Since e is the lightest edge in the graph, f is at least as heavy, so the new tree is no heavier. Repeating the argument for the next edge in weight order shows that Kruskal’s greedy sequence always reaches a minimum spanning tree.

      

    


    

      

        

        

          
          
        

      

      

      

    


    
7.6.2Union-Find Structure


    
A union-find structure keeps disjoint sets. Each set has a representative, and every element has a path to it. find(x) follows the path and returns the representative; unite links the representative of one set to the representative of another. Two elements are in the same set exactly when their representatives are equal.

Two more links would reach 2. Keeping the tree shallow — always attach the smaller set to the larger — makes every path O(log n).

      

    


    
Union by size is enough to keep the operations logarithmic. Path compression is the second optimisation: after find(x), point every node on the path directly at the representative. The amortised cost becomes O(α(n)), where α is the inverse Ackermann function — effectively a constant. Path compression is not always allowed: some applications, such as dynamic connectivity, depend on the structure of the links.


    
7.6.3Prim’s Algorithm


    
Prim grows a single tree instead of a forest. Start at an arbitrary node; then repeatedly add the lightest edge that connects the current tree to a node outside it. A priority queue holds the frontier edges, ordered by weight. Like Kruskal, the result is a minimum spanning tree, and the running time is O(n + m log m) — the same as Dijkstra’s.


    

      
Dijkstra
The key of a node is the distance from the source to that node.

      
Prim
The key of a node is the weight of one edge joining it to the growing tree.

    


    
In practice both Kruskal and Prim are efficient, and the choice is mostly a matter of taste. Kruskal needs an edge list and a union-find structure; Prim needs adjacency lists and a priority queue. Most competitive programmers reach for Kruskal, because the code is short and the union-find structure is useful elsewhere.


    
A graph is a compact way to write down what connects to what. Traversal tells you what is reachable, shortest paths tell you what it costs, topological order tells you what must come first, and a spanning tree tells you what is essential. The next chapter turns to algorithm design techniques that make these tools sharper.
