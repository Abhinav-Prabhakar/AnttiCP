7.1

Basics of Graphs

A graph is a set of nodes, a set of edges, and a question about how they connect.

Many programming problems can be solved by considering the situation as a graph and using an appropriate graph algorithm. This section goes through the terminology of graphs and their properties, and the data structures that represent them.

7.1.1Graph Terminology

Path

A path leads from a node to another node through the edges of the graph. The length of a path is the number of edges in it.

Cycle

A cycle is a path where the first and last node is the same.

Connected

A graph is connected if there is a path between any two nodes. The connected parts of a graph are called its components.

Tree

A tree is a connected graph that does not contain cycles.

Directed

In a directed graph, the edges can be traversed in one direction only. A node has an indegree and an outdegree.

Weighted

In a weighted graph, each edge is assigned a weight. The length of a path is the sum of its edge weights.

Neighbours

Two nodes are neighbors or adjacent if there is an edge between them. The degree of a node is the number of its neighbors.

Bipartite

A graph is bipartite if its nodes can be colored using two colors so that no adjacent nodes have the same color. It is bipartite exactly when it does not have an odd cycle.

Two facts worth keeping

The sum of degrees in a graph is always 2m, where m is the number of edges, because each edge increases the degree of exactly two nodes by one. So the sum of degrees is always even.

A graph is regular if the degree of every node is a constant d. A graph is complete if the degree of every node is n − 1, i.e., it contains all possible edges. In a directed graph, the indegree is the number of edges that end at a node, and the outdegree of a node is the number of edges that start at a node.

      7.2
      
Graph Traversal

    


    
Both traversals visit everything reachable. The difference is the order — and the order is the algorithm.

    
This section discusses two fundamental graph algorithms: depth-first search and breadth-first search. Both are given a starting node, and both visit every node reachable from it. The difference in the algorithms is the order in which they visit the nodes.


    
7.2.1Depth-First Search


    
Depth-first search (DFS) is a straightforward graph traversal technique. It begins at a starting node and proceeds to all other nodes reachable from it. Depth-first search always follows a single path as long as it finds new nodes. After this, it returns to previous nodes and begins to explore other parts of the graph. It keeps track of visited nodes, so it processes each node only once. The time complexity of depth-first search is O(n + m), because the algorithm processes each node and edge once.


    

      

        

        

          
          
        

      

      

      

    


    
7.2.2Breadth-First Search


    
Breadth-first search (BFS) visits the nodes of a graph in increasing order of their distance from the starting node. Thus, we can calculate the distance from the starting node to all other nodes using it. However, breadth-first search is more difficult to implement than depth-first search. The search goes one level after another: first the nodes at distance 1, then those at distance 2, and so on, until all nodes have been visited. A typical implementation uses a queue of nodes; at each step, the next node in the queue is processed.

7.2.3Applications


    
Both traversals can answer these questions, but depth-first search is usually easier to implement. The applications below assume an undirected graph.


    

      

        01
        
Connectivity

        
We can check if a graph is connected by starting at an arbitrary node and finding out if we can reach all other nodes. Similarly, we can find all connected components by always starting a new depth-first search if the current node does not belong to any component yet.

      

      

        02
        
Cycle detection

        
A graph contains a cycle if during a traversal, we find a node whose neighbor (other than the previous node in the current path) has already been visited. If a component contains c nodes and no cycle, it must contain exactly c − 1 edges; if there are c or more edges, the component contains a cycle.

      

      

        03
        
Bipartiteness

        
The idea is to pick two colors X and Y, color the starting node X, all its neighbors Y, all their neighbors X, and so on. If during the search we notice that two adjacent nodes have the same color, the graph is not bipartite. Otherwise the graph is bipartite and one coloring has been found.

      

    


    

    

      Why two colours are easy and three are not
      

        
This algorithm always works, because when there are only two colors available, the color of the starting node in a component determines the colors of all other nodes in the component. It does not matter what the colors are.

        
In the general case it is difficult to find out if the nodes can be colored using k colors so that no adjacent nodes have the same color. The problem is NP-hard already for k = 3.

      

    

  







  

    

      7.3
      
Shortest Paths

    


    
Weights turn a graph into a cost model. The shortest path is the cheapest way through, not necessarily the one with the fewest edges.

    
Finding a shortest path between two nodes of a graph has many practical applications. For example, in a road network we may want the shortest route between two cities. In an unweighted graph, the length of a path equals the number of its edges, and we can use breadth-first search to find a shortest path. However, this section focuses on weighted graphs, where finding shortest paths needs more sophisticated algorithms.


    
7.3.1Bellman–Ford Algorithm


    
The Bellman–Ford algorithm finds shortest paths from a starting node to all nodes of the graph. It can process any graph that does not contain a cycle with negative length, and it can detect such a cycle. It keeps track of distances from the starting node to all nodes: initially 0 to the starting node and infinite to any other node. It then reduces distances with edges that shorten the paths, until no distance can be reduced. It consists of n − 1 rounds, and on each round it goes through all edges and attempts to reduce the distances. The time complexity is O(nm), because there are n − 1 rounds, each iterating through all m edges. If there are no negative cycles, all distances are final after n − 1 rounds, because each shortest path can contain at most n − 1 edges.


    

    
The Bellman–Ford algorithm can also check if the graph contains a cycle with negative length. In this case, any path that contains the cycle can be shortened infinitely many times, so the concept of a shortest path is not meaningful. A negative cycle can be detected by running the algorithm for n rounds. If the last round reduces any distance, the graph contains a negative cycle. Note that this algorithm can be used to search for a negative cycle in the entire graph regardless of the starting node.


    
7.3.2Dijkstra’s Algorithm


    
Dijkstra’s algorithm finds shortest paths from the starting node to all nodes of the graph, like the Bellman–Ford algorithm. It is more efficient and can process large graphs. However, it requires that there are no negative weight edges in the graph. Like Bellman–Ford, Dijkstra’s algorithm maintains distances to the nodes and reduces them during the search. At each step, it selects an unprocessed node whose distance is as small as possible. Then, it goes through all edges that start at the node and reduces the distances. It processes each edge only once, because there are no negative edges. An efficient implementation requires a priority queue that contains the remaining nodes ordered by their distances. A new instance of a node is added whenever its distance changes. The time complexity is O(n + m log m), because it goes through all nodes and adds for each edge at most one distance to the priority queue.


    

      Why the greedy step is safe
      
When the smallest tentative distance is d, no route through an unsettled node can be shorter: every edge is non-negative, so any detour only adds to d. Its distance will never change again.

      
    


    

      

        
The efficiency of Dijkstra’s algorithm is based on the graph not having negative edges. If it has one, the algorithm may give incorrect results. Consider the graph below: the shortest path from node 1 to node 4 is 1 → 3 → 4 with length 1, but Dijkstra’s algorithm finds 1 → 2 → 4 by greedily following minimum weight edges.

        
This is not a bug to patch: it is the assumption that makes the algorithm fast. If negative edges are present, use Bellman–Ford, or reweight the graph when the structure allows it.

      

      
    


    
7.3.3Floyd–Warshall Algorithm


    
The Floyd–Warshall algorithm provides an alternative way to find shortest paths. Unlike the other algorithms in this chapter, it finds shortest paths between all node pairs in a single run. It maintains a matrix of distances between the nodes. The initial matrix is constructed from the adjacency matrix of the graph. On each round, it selects a new node that can act as an intermediate node, and reduces distances using it. The time complexity is O(n3), because it contains three nested loops over the nodes. Since the implementation is simple, it can be a good choice even if only a single shortest path is needed. However, the algorithm can only be used when the graph is so small that a cubic time complexity is fast enough.

      7.4
      
Directed Acyclic Graphs

    


    
A directed acyclic graph has a direction and no way back. That single restriction makes ordering — and dynamic programming — possible.

    
An important class of graphs are directed acyclic graphs, also called DAGs. Such graphs do not contain cycles, and many problems are easier to solve in them. In particular, we can always construct a topological sort and then apply dynamic programming.


    
7.4.1Topological Sorting


    
A topological sort is an ordering of the nodes of a directed graph such that if there is a path from node a to node b, then node a appears before node b. A directed graph has a topological sort exactly when it is acyclic. If the graph contains a cycle, no topological sort exists, because no node of the cycle can appear before the others.


    
Depth-first search can be used to check if a directed graph contains a cycle and, if it does not, to construct a topological sort. The idea is to go through the nodes and begin a depth-first search at each node that has not been processed yet. During the searches, a node has one of three states: 0 if it has not been processed, 1 if it is under processing, and 2 if it has been processed. Initially, every node is in state 0. When a search reaches a node for the first time, its state becomes 1, and after all edges from the node have been processed, its state becomes 2. If we arrive at a node whose state is 1, the graph contains a cycle, and no topological sort exists. If the graph is acyclic, we add each node to a list when its state becomes 2, and finally reverse the list.


    

    

      Cycle found during the search
      

        
If the search arrives at a node whose state is 1, the graph contains a cycle, and no topological sort exists.

      

    


    
7.4.2Dynamic Programming


    
Using dynamic programming, we can answer many questions regarding paths in directed acyclic graphs. For example, consider the number of paths from node a to node b. Let paths(x) denote the number of paths from node a to node x. As a base case, paths(a) = 1. To calculate other values, we use the recursive formula paths(x) = paths(s1) + paths(s2) + ⋯ + paths(sk), where s1, s2, …, sk are the nodes with an edge to x. Since the graph is acyclic, the values can be calculated in topological order.


    

    

      The four routes from 1 to 6
      

        

          1 → 2 → 3 → 6
          1 → 2 → 6
          1 → 4 → 5 → 2 → 3 → 6
          1 → 4 → 5 → 2 → 6
        

        
Counting paths is only well-defined because the graph is acyclic. In a graph with a cycle, a single walk could be extended by going around the cycle any number of times.

      

    


    
Dynamic programming can answer questions regarding shortest paths in general (not necessarily acyclic) graphs. If we know minimum distances from a starting node to other nodes (after Dijkstra’s algorithm, for example), we can create a directed acyclic shortest paths graph that indicates for each node the ways to reach it along a shortest path. Any dynamic programming problem can be represented as a directed acyclic graph where each node is a state and the edges indicate how the states depend on each other. For example, consider forming a sum of money n using coins {c1, c2, …, ck}. Each node then corresponds to a sum of money, and the edges show how the coins can be chosen. The shortest path from 0 to n corresponds to a solution with the minimum number of coins, and the total number of paths from 0 to n equals the total number of solutions.

  







  

    

      7.5
      
Successor Graphs

    


    
A successor graph gives every node exactly one outgoing edge. Each component is a single cycle with paths feeding into it.

    
Another special class of directed graphs are successor graphs. In those graphs, the outdegree of each node is 1, i.e., each node has a unique successor. A successor graph consists of one or more components, each of which contains one cycle and some paths that lead to it. Successor graphs are sometimes called functional graphs, because they correspond to a function succ(x) that defines the edges.

7.5.1Finding Successors


    
Since each node of a successor graph has a unique successor, we can define a function succ(x, k) that gives the node we reach if we begin at node x and walk k steps forward. Walking k steps from x takes O(k) time. However, using preprocessing, any value of succ(x, k) can be calculated in O(log k) time. Let u denote the maximum number of steps we will ever walk. We precalculate all values of succ(x, k) where k is a power of two and at most u, using the recurrence succ(x, 2k) = succ(succ(x, k), k). Precalculating these values takes O(n log u) time, because O(log u) values are calculated for each node. After the precalculation, any succ(x, k) can be calculated by presenting k as a sum of powers of two.


    

    
7.5.2Cycle Detection


    
Consider a successor graph that only contains a path that ends in a cycle. If we begin our walk at the starting node, what is the first node in the cycle and how many nodes does the cycle contain? A simple way to detect the cycle is to walk in the graph and keep track of all visited nodes. Once a node is visited for the second time, it is the first node in the cycle. This method works in O(n) time and uses O(n) memory. However, better algorithms exist. Their time complexity is still O(n), but they only use O(1) memory.


    

      

        
One such algorithm is Floyd’s algorithm, which walks in the graph using two pointers a and b. Both begin at the starting node x. On each turn, a walks one step forward and b walks two steps forward. The process continues until the pointers meet. At this point, a has walked k steps and b has walked 2k steps, so the length of the cycle divides k. Thus, the first node in the cycle is found by moving a to node x and advancing the pointers step by step until they meet again.

        
After this, the length of the cycle can be calculated as follows.

        

          1 a ← succ(a), b ← succ(succ(b))
          2 repeat until a = b
          3 a ← start; advance both until a = b
          4 count steps from a back to a
        

      

      
    

  







  

    

      7.6
      
Minimum Spanning Trees

    


    
A spanning tree keeps every node and just enough edges to connect them. The minimum spanning tree is the cheapest such skeleton.

    
A spanning tree contains all nodes of a graph and some edges so that there is a path between any two nodes. Spanning trees are connected and acyclic. The weight of a spanning tree is the sum of its edge weights. A minimum spanning tree is a spanning tree whose weight is as small as possible; a maximum spanning tree is one whose weight is as large as possible. A graph may have several minimum and maximum spanning trees, so the trees are not unique. The same algorithms also find maximum spanning trees by processing the edges in reverse order.

7.6.1Kruskal’s Algorithm


    
Kruskal’s algorithm builds a minimum spanning tree by greedily adding edges. The initial spanning tree only contains the nodes and no edges. Then it goes through the edges ordered by weight and adds an edge if it does not create a cycle. The algorithm maintains the components of the graph. Initially, each node belongs to a separate component. When an edge is added, two components are joined. Finally, all nodes belong to the same component, and a minimum spanning tree has been found.

      Why the greedy choice is safe
      

        
It is a good question why Kruskal’s algorithm works. Why does the greedy strategy guarantee a minimum spanning tree? Suppose that a minimum spanning tree would not contain the minimum weight edge 5–6. We do not know its exact structure, but it has to contain some edges. It cannot be a minimum spanning tree, because we can remove an edge from it and replace it with the minimum weight edge 5–6. This produces a spanning tree whose weight is smaller. For this reason, it is always optimal to include the minimum weight edge. Using a similar argument, it is also optimal to add the next edge in weight order, and so on. Hence, Kruskal’s algorithm always produces a minimum spanning tree.

      

    


    

      

        

        

          
          
        

      

      

      

    


    
7.6.2Union-Find Structure


    
A union-find structure maintains a collection of disjoint sets, so no element belongs to more than one set. Two O(log n) time operations are supported: unite joins two sets, and find finds the representative of the set that contains a given element. One element in each set is its representative, and there is a path from any other element to the representative. Two elements belong to the same set exactly when their representatives are the same.

Always connect the representative of the smaller set to that of the larger set (if the sets are equal in size, either choice works). Then the length of any path is O(log n), so we can find the representative of any element by following the corresponding path.

      

    


    
Path compression is an alternative way to implement the find operation. Each element in the path directly points to its representative after the operation. Using this function, the union-find operations work in amortized O(α(n)) time, where α(n) is the inverse Ackermann function, which grows very slowly (it is almost a constant). However, path compression cannot be used in some applications, such as the dynamic connectivity algorithm.


    
7.6.3Prim’s Algorithm


    
Prim’s algorithm is an alternative way to construct minimum spanning trees. It first adds an arbitrary node to the tree, and then always chooses a minimum weight edge that adds a new node. Finally, all nodes have been added and a minimum spanning tree has been found. Prim’s algorithm resembles Dijkstra’s algorithm. The difference is that Dijkstra’s algorithm selects a node with minimum distance from the starting node, but Prim’s algorithm selects a node that can be added to the tree using a minimum weight edge. Like Dijkstra’s algorithm, Prim’s algorithm can be implemented using a priority queue. The priority queue contains all nodes that can be connected to the current component with a single edge, ordered by edge weight. The time complexity of Prim’s algorithm is O(n + m log m), which equals that of Dijkstra’s algorithm.


    

      
Dijkstra
The key of a node is the distance from the source to that node.

      
Prim
The key of a node is the weight of one edge joining it to the growing tree.

    


    
In practice, Prim’s and Kruskal’s algorithms are both efficient, and the choice is a matter of taste. Still, most competitive programmers use Kruskal’s algorithm.


    
A graph is a compact way to write down what connects to what. Traversal tells you what is reachable, shortest paths what it costs, topological order what must come first, and a spanning tree what is essential. The next chapter turns to algorithm design techniques that make these tools sharper.
