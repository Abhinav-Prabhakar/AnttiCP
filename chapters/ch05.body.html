5.1

Dynamic Arrays

A vector is an array that keeps its promises at the end.

In C++, ordinary arrays are fixed-size: their size cannot change after creation. A dynamic array's size can change during execution. The standard library provides several dynamic arrays, the most useful being the vector structure.

Vectors: size, capacity, and the cost of growing

A vector is a dynamic array that efficiently adds and removes elements at the end. push_back adds an element, size returns the number of elements, back returns the last element, and pop_back removes the last element. Elements can then be accessed like in an ordinary array. push_back and pop_back work in O(1) time on average. In practice, a vector is almost as fast as an ordinary array.

Iterators and ranges: begin, end, and one past the last

An iterator is a variable that points to an element of a data structure. The iterator begin points to the first element, and the iterator end points to the position after the last element. Note the asymmetry: begin() points to an element inside the structure, while end() points outside it. A range is a sequence of consecutive elements. It is usually given by iterators to its first element and the position after its last. Together, begin() and end() define a range containing all elements. The standard library functions typically operate with ranges.

Deques, stacks, and queues

A deque is a dynamic array that can be efficiently manipulated at both ends. Like a vector, it provides push_back and pop_back, but also push_front and pop_front. Its operations also work in O(1) average time. However, deques have larger constant factors than vectors, so use one only if you need both ends. C++ also provides two specialized structures, by default based on a deque. A stack has push and pop for inserting and removing elements at the end, and top, which retrieves the last element. In a queue, elements are inserted at the end and removed from the front, with front and back accessing the first and last element.

5.2

Set Structures

A set trades order for speed — or speed for order. Know which one you are buying.

A set maintains a collection of elements. Its basic operations are insertion, search and removal. The C++ standard library contains two set structures: set is based on a balanced binary search tree and its operations work in O(log n) time, while unordered_set is based on a hash table, where operations work, on average, in O(1) time.

Sets and multisets

The function insert adds an element, count returns the number of occurrences of an element, and erase removes one. An important property of sets is that all their elements are distinct: count returns either 0 (the element is not in the set) or 1 (it is), and insert never adds an element that is already there. find(x) returns an iterator to an element whose value is x. However, if the set does not contain x, the iterator will be end(). Since the elements are sorted, we can find the smallest and largest value. The set structure also provides lower_bound(x) and upper_bound(x), which return an iterator to the smallest element whose value is at least or larger than x, respectively. A multiset is a set that can have several copies of the same value. erase removes all copies of a value; often only one should be removed, which s.erase(s.find(5)) does.

The main difference is that set is ordered, while unordered_set is not. Thus, if we want to maintain the order of the elements, we have to use set. The worst-case time complexity of the operations is O(n), but this is very unlikely to occur.

set · O(log n) unordered_set · O(1) average multiset · duplicates
Which one should you use?

Both are efficient, and often either can be used. Since they are used the same way, the choice depends on whether we want to maintain the order of the elements: if we do, we have to use set.

Hash tables: buckets and collisions

A hash table maps each key to a bucket, usually with a function such as h(k) = k mod m. Different keys can land in the same bucket; the table resolves the collision by chaining the values. With a good hash function the chains stay short, which is where the average O(1) comes from.

Maps: keys that are not indices

A map is a set of key–value pairs. It can also be seen as a generalized array. While the keys in an ordinary array are always consecutive integers 0, 1, …, n − 1, where n is the size of the array, the keys in a map can be of any data type and need not be consecutive. The standard library contains two map structures corresponding to the set structures: map is based on a balanced binary search tree and access takes O(log n) time, while unordered_map uses hashing and access takes O(1) time on average.

If a key is requested but the map does not contain it, the key is automatically added with a default value. For example, the key “aybabtu” with value 0 is added to the map. In a contest, that can turn a lookup into a silent update.

The function count checks if a key exists in a map. We can then print all keys and values in a map.

Priority queues: only the top matters

A priority queue is a multiset that supports insertion and, depending on the type, retrieval and removal of either the minimum or maximum element. Insertion and removal take O(log n) time; retrieval takes O(1). A priority queue is usually based on a heap structure, a special binary tree. While a multiset provides all the operations of a priority queue and more, the priority queue has smaller constant factors. Thus, if we only need to find minimum or maximum elements efficiently, a priority queue is a good choice over a set or multiset.

Policy-based sets

The g++ compiler also provides some non-standard data structures. They are called policy-based structures. An indexed_set is like set but can be indexed like an array: we have access to the indices the elements would have in a sorted array. find_by_order returns an iterator to the element at a given position, and order_of_key returns the position of a given element. If the element does not appear in the set, we get the position it would have. Both functions work in logarithmic time.

Experiments

Two O(n log n) algorithms can differ by a factor of ten.

In this section we present some results on the practical efficiency of the data structures in this chapter. Time complexities are a great tool, but they do not tell the whole truth about efficiency, so it is worthwhile to experiment with real implementations and data sets.

What the measurements say

It turns out that the unordered_set algorithm is about two times faster than the set algorithm, and the sorting algorithm is more than ten times faster than set. Both the set algorithm and the sorting algorithm work in O(n log n) time; still the latter is much faster. The reason is that sorting is a simple operation, while the balanced binary search tree used in set is a complex data structure.

While unordered_map is about three times faster than map, an array is almost a hundred times faster. Thus, arrays should be used whenever possible instead of maps. Note also that while unordered_map provides O(1) operations, large constant factors hide in the structure.

Are priority queues really faster than multisets? It turns out that in this problem a priority_queue is about five times faster than a multiset.

The best data structure is the one whose promises match the question. A vector gives you a sequence; a set gives you order; a hash table gives you speed; a priority queue gives you the top. Choose the promise, then the container.
