4.1

Sorting Algorithms

Sorting is not the goal. It is the move that makes every later step cheap.

Given an array of n elements, the sorting problem asks for the same elements in increasing order. An O(n2) algorithm is easy to design. The interesting part is doing better.

This section follows the book through a simple quadratic sort, an efficient recursive sort, the proof that comparison sorting cannot beat O(n log n), and a linear-time sort that avoids comparisons altogether. It ends where most contests begin: with the standard library.

O(n2)bubble sort
O(n log n)merge sort
O(n)counting sort

The third bound needs a condition: the values are integers in 0 … c with c = O(n).

Bubble sort, and what an inversion costs

Bubble sort makes n rounds over the array. On each round it compares consecutive elements and swaps them when they are in the wrong order. After the first round the largest element is in its final place; after k rounds the k largest are. The whole array is sorted after n rounds, at a cost of O(n2) time.

An inversion is a pair of indices a < b with array[a] > array[b]. A sorted array has none; a reversed array has n(n − 1)/2, the maximum possible. Swapping two consecutive elements that are out of order removes exactly one inversion. So an algorithm that only swaps neighbours needs at least a quadratic number of swaps in the worst case.

Merge sort: divide, then merge

To beat quadratic time, a sort has to move elements across different parts of the array. Merge sort does exactly that. It splits the array in half, sorts each half recursively, and merges the two sorted halves in linear time. There are log n levels of splitting, and each level does O(n) work in total, which gives O(n log n).

The comparison lower bound

Can a comparison sort be faster than O(n log n)? If the algorithm only learns about the array by asking “is x < y?”, then each answer is one branch of a decision tree. The leaves are the possible sorted orders, and there are n! of them.

A binary tree with n! leaves has height at least log2(n!). Using the last n/2 terms of that sum gives

log2(n!) ≥ (n/2) log2(n/2) = Ω(n log n).

So no comparison sort can guarantee a better worst-case bound. The proof does not apply to algorithms that use the values themselves — which is the opening for counting sort.

Counting sort: use the value as an index

Counting sort does not compare elements at all. If every value is an integer in 0 … c and c = O(n), it builds a bookkeeping array: position x stores how many times x occurs. Building the counts takes one pass; writing the sorted array takes another. Total: O(n). The price is the condition on the value range.

Sorting in practice

In a contest, write sort, not a home-made sort. The C++ standard library requires sort to run in O(n log n) time, and the implementation is correct and fast. It works on vectors, ordinary arrays, and even strings.

C++ · the library sort.cpp 
vector<int> v = {4,2,5,3,5,8,3};
sort(v.begin(), v.end());          // [2, 3, 3, 4, 5, 5, 8]
sort(v.rbegin(), v.rend());        // reverse order

int a[] = {4,2,5,3,5,8,3};
sort(a, a+n);

string s = "monkey";
sort(s.begin(), s.end());          // "ekmnoy"
How sort decides the order

Most types already have a comparison. Numbers compare by value, strings alphabetically, pairs by their first element and then their second, and tuples lexicographically from the first component onward.

For a struct, define operator<. For an external rule, pass a comparison function to sort. The function returns true when the first argument must come before the second.

struct point {
    int x, y;
    bool operator<(const point &p) {
        if (x == p.x) return y < p.y;
        else return x < p.x;
    }
};

bool comp(string a, string b) {
    if (a.size() == b.size()) return a < b;
    else return a.size() < b.size();
}
sort(v.begin(), v.end(), comp);
4.2

Solving Problems by Sorting

A sorted order turns a global question into a local one.

Brute force often costs O(n2) because it compares everything with everything. Sort first and many of those comparisons disappear: equal elements become neighbours, events acquire a timeline, and a greedy choice becomes provably safe.

Duplicates become neighbours

To check whether every element is unique, compare all pairs — O(n2). Or sort the array and inspect consecutive elements — O(n log n). The same idea counts distinct values, finds the most frequent value, and finds the closest pair by difference.

One adjacent pair is enough to answer the question.

Sweep line: give every change a time

A sweep line models a problem as events in sorted order. In the restaurant problem, each customer contributes two events: an arrival and a leaving. Sort the events by time, then walk through them with a counter. The largest counter value is the maximum number of customers present at once. Sorting costs O(n log n); the sweep itself is linear.

Scheduling: choose the event that ends first

Given n events with start and end times, choose as many non-overlapping events as possible. Sorting by length fails; sorting by start time fails too. Sorting by ending time works: always take the compatible event that finishes earliest. An exchange argument shows that choosing a later finish can never leave more room for the rest.

Tasks and deadlines: sort by duration

Each task has a duration and a deadline. Finishing a task at time x earns d − x points, where d is its deadline. Surprisingly, the deadlines do not affect the optimal order at all: perform the tasks in increasing order of duration.

Why swapping two tasks always helps

Suppose task X of duration a runs before task Y of duration b, with a > b. Swap them. The later task finishes a − b time units earlier, so it gains a − b points. The earlier task now finishes a − b units later, so it loses a − b points. Since a > b, the gain is positive: the swap improves the total. Hence no optimal schedule puts a longer task before a shorter one.

4.3

Binary Search

If the data is already ordered, a search should not look at all of it.

Binary search finds a value in a sorted array in O(log n) time. It maintains an active subarray and compares the target with the middle element; one comparison discards half of the remaining range. The same halving idea can search an entire space of possible answers.

The classic search

Keep indices a and b for the active range. At each step, inspect the middle index k. If the value is too small, the answer must be to the right; if it is too large, to the left. When a passes b, the range is empty.

Searching an answer space

Sometimes the array is not the point — the answer is. Suppose valid(x) is false for every x < k and true for every x ≥ k. Then binary search can find k without scanning every candidate: search for the largest x with valid(x) false, and add one.

In the jobs example, machine i can process ⌊x/pi⌋ jobs in x time. The predicate is true when the sum of those counts reaches k. Each check costs O(n); binary search makes O(log z) checks, where z is an upper bound for the answer. The total is O(n log z).

The jump method

The book gives a second implementation. Start at index 0 with jump length n/2, halve the jump on every round, and jump forward while the landing value is at most the target. The while loop runs at most twice per jump length, so the method is also O(log n).

int k = 0;
for (int b = n/2; b >= 1; b /= 2) {
    while (k+b < n && array[k+b] <= x) k += b;
}
if (array[k] == x) {
    // x found at index k
}

Sorting gives the order; binary search spends it. Together they turn a scan into a logarithm — and a difficult search into a small number of comparisons.
