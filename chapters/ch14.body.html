String Algorithms

14.1

Basic Topics

Almost every string algorithm is a way of not comparing more characters than necessary.

All strings in this chapter are zero-indexed: a string s of length n consists of characters s[0], s[1], …, s[n−1]. The notation s[a…b] means the consecutive characters from a to b. A prefix starts at position 0, a suffix ends at position n−1, and a subsequence may skip characters while keeping the rest in order.

NVELO occupies positions 1–5, with no gaps.

substring consecutive characters, s[a…b]
prefix s[0…k], always starts at the beginning
suffix s[k…n−1], always ends at the end
subsequence characters in order, gaps allowed

Every substring is a subsequence, but not every subsequence is a substring: NVELO cannot skip a character, while NEP can. Comparing two strings of length n costs O(n) in the worst case — the rest of the chapter is about paying less.

14.1.1

Trie Structure

A trie is a rooted tree that stores a set of strings. Each string is a character chain from the root, so strings that share a prefix also share a chain. The four words CANAL, CANDY, THE, and THERE need only eleven edges — the second A in CANAL and the Y in CANDY branch from the same CAN.

A filled node marks the end of a word. Searching and inserting both follow or extend one chain, so both take O(n) time for a string of length n.

Choose a query to follow its chain from the root.

Storing a trie

A trie fits in a two-dimensional array int trie[N][A], where N is the maximum total length of the stored strings and A is the alphabet size. Nodes are numbered so that the root is 0, and trie[s][c] gives the next node from node s using character c.

Storing at each node the number of strings that pass through it turns the trie into a prefix counter: the number of strings starting with a given prefix is then read from one node.

14.1.2

Dynamic Programming

Two string problems recur constantly: the longest common subsequence, and the cheapest way to turn one string into another. Both are tables filled one cell at a time.

Longest common subsequence

The longest string that appears as a subsequence in both TOUR and OPERA is OR. Let lcs(i, j) be the answer for the prefixes x[0…i] and y[0…j]:

lcs(i, j) = lcs(i−1, j−1) + 1   if x[i] = y[j]

lcs(i, j) = max(lcs(i, j−1), lcs(i−1, j))   otherwise

O(nm) time, O(nm) memory.

Edit distance

The edit distance between LOVE and MOVIE is 2: modify L to M, then insert I. Allowed operations are insert, remove, and modify one character.

edit(a, b) = min( edit(a, b−1) + 1, edit(a−1, b) + 1, edit(a−1, b−1) + cost )

cost = 0 when the characters match, otherwise 1. Again O(nm).

The last cell holds the answer: 2 — the length of OR.

14.2

String Hashing

A hash value is a fingerprint: one integer that stands in for a whole string.

If two strings are equal, their hash values are equal. Comparing two integers is O(1), so a fingerprint can replace a character-by-character comparison. The fingerprint is not unique — that risk is handled in 14.2.3.

14.2.1

Polynomial Hashing

The usual implementation is polynomial hashing. Interpret the characters as codes and evaluate a polynomial in a constant A, then take the result modulo a constant B:

hash(s) = (s[0]An−1 + s[1]An−2 + ⋯ + s[n−1]A0) mod B

For ABACB the codes are A = 65, B = 66, C = 67. With A = 3 and B = 97 the polynomial is 7897, which leaves the hash value 40.

Applications

Because hashing compares any two substrings in O(1), a brute-force algorithm often becomes efficient after replacing its inner comparison. Three examples show the pattern.

01 · Pattern matching

Find every occurrence

Compare the pattern's hash with the hash of every length-3 window. Two equal hashes mean two candidate matches — here at positions 0 and 5.

14.2.3

Collisions and Parameters

A collision means two different strings share a hash value. It is always possible, because there are more strings than hash values. Whether it matters depends on how many comparisons are made.

1

x is compared with y. Collision probability 1/B.

2

x is compared with y1…yn. One or more collisions: 1 − (1 − 1/B)n.

3

All pairs among n strings are compared. This is the birthday paradox, and it is where B ≈ 109 stops being enough.

Table 14.1 · n = 106

Every pair among a million strings: with B ≈ 109 a collision is certain. This is the birthday paradox — and the reason to use two hashes.

Making collisions negligible

Two hash values with different parameters behave like one hash with B ≈ 1018, which makes an accidental collision very unlikely. Some people choose B = 232 or 264 because overflow does the modulo for free, but inputs that force collisions for powers of two can be constructed — avoid them.

The table is the whole argument: one comparison is cheap to protect, all pairs are not. Choose the tool by the number of comparisons, not by habit.

14.3

Z-Algorithm

The Z-array records, at every position, how much of the string's own beginning repeats there.

For each k, z[k] is the length of the longest substring starting at k that is also a prefix of s. So z[k] = p means s[0…p−1] = s[k…k+p−1], and the next characters differ (or the string ends).

14.3.1

Constructing the Z-Array

The Z-algorithm fills the array left to right in O(n). It keeps one range [x, y] such that s[x…y] is a prefix of s, z[x] is known, and y is as large as possible. Inside that box, characters can be copied instead of compared.

  1. 1

    y < k. No box covers k. Compare from scratch, character by character.

  2. 2

    k + z[k−x] ≤ y. The match stays inside the box, so z[k] = z[k−x]. No comparisons.

  3. 3

    k + z[k−x] > y. The match reaches past the box. Start at y−k+1 and continue comparing.

Every successful comparison moves y one step right, so the total number of comparisons is O(n).

14.3.2

Applications

The Z-array solves the same problems as hashing, but it is exact: there is no collision, no random constant, and no probability to argue about.

Hashing and the Z-algorithm are interchangeable for many tasks. Hashing compares any two substrings in O(1); the Z-algorithm reads one string once and never guesses.

14.4

Suffix Arrays

The suffix array is the string's table of contents: every suffix, listed in lexicographic order.

The suffix array of a string only stores starting positions. For ABAACBAB it is [2, 6, 0, 3, 7, 1, 5, 4]: the smallest suffix starts at 2, the next at 6, and the largest at 4.

Sorting the suffixes of an n-character string by comparing them directly takes O(n2 log n) in the worst case, since each comparison can scan O(n) characters. Prefix doubling reduces that to O(n log2 n) — or O(n log n) with a linear-time sort of the labels.

Unlike hashing and the Z-algorithm, a suffix array is built once and then answers queries for different patterns. The patterns do not need to be known in advance.

14.4.1

Prefix Doubling Method

Prefix doubling sorts substrings of length 1, then 2, then 4, and so on. Each round labels every substring with an integer that preserves both equality and order, so the next round can compare pairs of labels instead of characters.

How a pair becomes a label

On round i, a substring of length 2i is split into two halves of length 2i−1. Its initial label is the pair of the halves' labels; a missing second half has label 0. All initial labels are then sorted and replaced by consecutive integers 1, 2, 3, …

Initial label (2, 1). Two labels are smaller — (1, 6) and (2, 0) — so the final label is 3.

After round 2 this string's labels are already unique, because the first four characters decide the order of every suffix. The final labels read in position order are 3 6 1 4 8 7 2 5 — which is exactly the inverse of the suffix array.

Finding Patterns

A sorted list can be searched by halving. Process the pattern one character at a time and keep the range of suffixes that begin with the prefix read so far; each character narrows the range with two binary searches.

14.4.3

LCP Arrays

The LCP array gives, for each suffix, the length of the longest common prefix it shares with the next suffix in the suffix array. The last suffix has no LCP value.

Kasai's algorithm builds it in O(n). The key observation: if a suffix has LCP value x, removing its first character leaves a suffix whose LCP value is at least x−1. For example, BAACBAB has LCP 2, so AACBAB has LCP at least 1.

Then only O(n) character comparisons are needed in total, because the known lower bound is never re-checked.

Counting distinct substrings

A string of length n has n(n+1)/2 substrings, but the LCP sum counts the ones that repeat at the start of a suffix. Subtract it:

n(n+1)/2 − c = 8 · 9 / 2 − 7 = 29

ABAACBAB has 36 substrings in total, and the seven repeats counted by the LCP array leave 29 distinct ones.

The suffix array answers questions the other tools cannot: many patterns, asked later, over the same text. Hashing gives a fingerprint, the Z-algorithm gives a scan, and the suffix array gives an index — the structure a search engine keeps.
