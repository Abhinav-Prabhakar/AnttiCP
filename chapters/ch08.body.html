8.1

Bit-Parallel Algorithms

A register is not so much a number as a row of decisions — and one instruction can act on all of them.

Bit-parallel algorithms are based on the fact that individual bits of numbers can be manipulated in parallel with bit operations. A way to design an efficient algorithm is to represent its steps so bit operations can implement them.

Minimum distance among many strings

The Hamming distance hamming(a, b) between two strings a and b of equal length is the number of positions where they differ. For example, hamming(01101, 11001) = 2. Consider the problem: given n bit strings, each of length k, calculate the minimum Hamming distance between two strings.

A straightforward way to solve the problem is to go through all pairs of strings and calculate their Hamming distances, which yields an O(n2k) time algorithm. However, since the strings consist of bits, we can store them as integers and calculate distances using bit operations. If k ≤ 32, the strings fit in int values. Then xor constructs a string with one bits where a and b differ, and __builtin_popcount counts the one bits.

For example, the answer for [00111, 01101, 11110] is 2, because hamming(00111, 01101) = 2, hamming(00111, 11110) = 3, and hamming(01101, 11110) = 3.

8.1.2

Counting Subgrids

As another example, given an n × n grid of black (1) and white (0) squares, count the subgrids whose corners are all black.

There is an O(n3) time algorithm: go through all O(n2) pairs of rows, and for each pair (a, b) count in O(n) time the columns with a black square in both rows. Then count(count − 1)/2 gives the number of subgrids whose first row is a and last row is b. To create a bit-parallel algorithm, represent each row k as an n-bit bitset row[k] where one bits denote black squares. Then we count the columns where both rows have black squares using an and operation: (row[a] & row[b]).count().

Why this is O(n³ / w), not O(n³)

There are still O(n2) row pairs; the cost of each pair changes: a machine word holds w columns, so the n column tests become n/w word operations. With 64-bit words, the inner work is roughly 64 times cheaper before popcount.

The book's bit-parallel version runs up to 30 times faster than the triple loop on grids up to 3000 × 3000.

8.1.3

Reachability in Graphs

Given a directed acyclic graph of n nodes, consider calculating for each node x a value reach(x): the number of nodes reachable from x. Dynamic programming solves the problem in O(n2) time by constructing for each node a list of reachable nodes. To create a bit-parallel algorithm, we represent each list as a bitset of n bits, so the union of two lists is computed with an or operation.

The algorithm uses a great amount of memory for large n. In many contests, the limit may be 512 MB or lower; at n = 105 the table already needs 1,250 MB.

8.2

Amortized Analysis

The worst single operation can be expensive. What matters is what the whole sequence costs.

The structure of an algorithm often directly tells us its time complexity, but sometimes a straightforward analysis does not give a true picture. Amortized analysis analyzes a sequence of operations whose time complexity varies. The idea is to estimate the total time used by all such operations, instead of focusing on individual ones.

Amortized analysis is often used to estimate the number of operations performed on a data structure. The operations may be distributed unevenly, so most occur during a certain phase of the algorithm, but the total number is limited.

Amortized analysis asks a different question: over n operations, how many times can each element be touched? If the answer is a constant, the occasional expensive step does not change the total.

The accounting view

Charge every element one unit when it enters the structure and one for the single time it can leave. A step that removes five elements is not free, but those removals were already paid for. The total bill is at most 2n.

8.2.1

Two Pointers Method

In the two pointers method, two pointers walk through an array. Both move in one direction only, which keeps the algorithm efficient. As a first example of how to apply the technique, consider a problem where we are given an array of n positive integers and a target sum x, and we want to find a subarray whose sum is x, or report that none exists. The two pointers method solves it in O(n) time. The idea is to keep pointers to the first and last value of a subarray. On each turn, the left pointer moves one step right, and the right pointer moves right as long as the subarray sum is at most x. If the sum becomes exactly x, a solution has been found.

The same idea, sorted

Another two-pointer problem is 2SUM: given an array of n numbers and a target sum x, find two values whose sum is x, or report that none exist. To solve the problem, we first sort the array values in increasing order. The left pointer starts at the first value and moves one step right each turn. The right pointer starts at the last value and moves left until the sum of the two values is at most x. If the sum is exactly x, a solution has been found.

The running time is O(n log n), because it first sorts the array and then both pointers move O(n) steps. The problem can also be solved in O(n log n) time using binary search.

8.2.2

Nearest Smaller Elements

As an example, suppose we want to find for each array element the nearest smaller element, i.e., the first smaller element that precedes it. No such element may exist, in which case the algorithm reports this. We go through the array from left to right and maintain a stack. At each position, we remove elements until the top is smaller than the current element, or the stack is empty. Then the top is the nearest smaller element, or if the stack is empty, there is none. Finally, we add the current element to the stack.

The efficiency depends on the total number of stack operations. If the current element is larger than the top, it is added directly, which is efficient. However, the stack can contain several larger elements and removing them takes time. Still, each element is added exactly once and removed at most once. Thus, each element causes O(1) stack operations, and the algorithm works in O(n) time.

8.2.3

Sliding Window Minimum

A sliding window is a constant-size subarray that moves from left to right through an array. At each position, we want some information about the elements inside. Here we focus on the sliding-window minimum: report the smallest value inside each window. The minima can be calculated with the same idea as the nearest smaller elements. This time we maintain a queue where each element is larger than the previous one, and the first element is always the minimum inside the window.

Add 2, then 1: 1 removes 2 because it is smaller. Continue with 4 and 5; the deque holds [1, 4, 5] and the minimum is 1.

After each window move, we remove elements from the end of the queue until the last element is smaller than the new element, or the queue is empty. We also remove the first element if it is no longer inside the window. Finally, we add the new element to the queue. Since each array element is added exactly once and removed at most once, the algorithm works in O(n) time.

This is the same accounting argument as the stack: the deque may grow and shrink dramatically between steps, but no value is pushed or removed twice.

8.3

Finding Minimum Values

If a function only falls and then rises, its bottom can be cornered without visiting every point.

Suppose that a function f(x) first only decreases, then attains its minimum, then only increases. If our function has this property, we can find its minimum efficiently.

8.3.1

Ternary Search

Ternary search finds the minimum of a function that first decreases and then increases. Assume that the value of x minimizing f(x) is in a range [xL, xR]. Divide the range into three equal parts [xL, a], [a, b], and [b, xR] by choosing a = (2xL + xR)/3 and b = (xL + 2xR)/3. If f(a) < f(b), the minimum must be in [xL, b]; otherwise it must be in [a, xR]. Continue recursively until the range is small enough. Since the new range is always 2/3 of the previous, the algorithm works in O(log n) time, where n is the number of elements in the original range.

In practice, the parameters are often integers, and the search ends when the range contains one element. With integer parameters, binary search also works, because it suffices to find the first position x for which f(x) ≤ f(x + 1).

8.3.2

Convex Functions

A function is convex if a line segment between any two points on its graph lies above or on the graph. If the minimum of a convex function is in range [xL, xR], ternary search can find it. However, several points of a convex function may have the minimum value. For example, f(x) = 0 is convex and its minimum is 0.

Convex functions have useful properties: if f(x) and g(x) are convex, then f(x) + g(x) and max(f(x), g(x)) are convex. For example, if we have n convex functions f1, f2, …, fn, we immediately know that also the function f1 + f2 + … + fn has to be convex and we can use ternary search to find its minimum value.

The optimal x is always the median, i.e., the middle element after sorting. The median is always optimal, because if x is smaller than the median, the sum becomes smaller by increasing x, and if x is larger than the median, the sum becomes smaller by decreasing x. If n is even and there are two medians, both medians and all values between them are optimal. For squared distances the optimal x is the average.

Why the average minimizes squares

Expand the sum: n x2 − 2x(a1 + … + an) + (a12 + … + an2). The last bracket does not depend on x. With s = the sum of the numbers, the rest is an upward parabola with roots 0 and 2s/n; its lowest point is halfway between them, at s/n.

For the example, s/n = (1 + 2 + 9 + 2 + 6)/5 = 4, which produces 46.

Bit operations compress a loop, amortized analysis a sequence, and convexity a search. Each one removes work the problem never required.
