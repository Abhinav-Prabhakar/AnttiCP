15.1

Square Root Techniques

A square root is a poor man’s logarithm: O(√n) is better than O(n) but worse than O(log n).

In any case, many data structures and algorithms involving square roots are fast and usable in practice. This section shows some examples of how square roots are used in algorithm design.

15.1.1

Data Structures

Sometimes we can create an efficient data structure by dividing an array into blocks of size √n and maintaining information inside each block. For example, suppose that we process two types of queries: modifying array values and finding minimum values in ranges. A segment tree supports both in O(log n) time, but next we solve the problem in a simpler way, with O(√n) operations.

We divide the array into blocks of √n elements and maintain the minimum inside each block. When a value changes, its block is updated in O(√n) time by going through the values inside it. To calculate the minimum in a range, we split it into single values at the ends and whole blocks between them. The answer is either a single value or a block minimum. Since there are O(√n) single elements and O(√n) blocks, the query takes O(√n) time.

15.1.2

Subalgorithms

Next we discuss two problems solved efficiently by creating two subalgorithms, each specialized for a different kind of situation during the algorithm. Either could solve the problem alone, but combining them gives an efficient algorithm.

Letter distances

Our first problem is this: we are given an n × n grid where each square has a letter. What is the minimum Manhattan distance between two squares with the same letter? For example, the minimum distance is 2 between the two squares with letter D. We go through all letters and, for each letter c, find the minimum distance between two squares with c. Consider two algorithms for a fixed letter c:

Algorithm 1 All pairs O(k2)

Go through all pairs of squares with letter c and find the closest pair. This works in O(k2) time, where k is the number of squares with c.

Algorithm 2 Multi-source BFS O(n2)

Perform a breadth-first search that simultaneously begins at each square with letter c. The search takes O(n2) time.

pairs BFS
k ≤ xk > x

However, we can combine the two algorithms so that they function as subalgorithms of a single algorithm. For each color c, we decide which to use: Algorithm 1 works well if k is small, Algorithm 2 when k is large. Fix a constant x and use Algorithm 1 if k is at most x, otherwise Algorithm 2. Choosing x = √n2 = n gives an O(n3) algorithm. Each square processed by Algorithm 1 is compared with at most n other squares, so those take O(n3) time. And since at most n colors appear in more than n squares, Algorithm 2 is performed at most n times, with total running time also O(n3).

A second example

The black squares game

As another example, consider this game: an n × n grid has exactly one black square and all others white. On each turn, a white square is chosen and we calculate the minimum Manhattan distance between it and a black square. The white square is then painted black. This continues for n2−1 turns, after which all squares are black.

We process the turns in batches of k. Before each batch, we calculate for every square its minimum distance to a black square, in O(n2) time using breadth-first search. While processing a batch, we keep a list of squares painted black during it. The minimum distance is then either the precalculated distance or a distance to one of those squares. The list has at most k values, so going through it takes O(k) time. Choosing k = √n2 = n gives an O(n3) algorithm.

15.1.3

Integer Partitions

Suppose a stick of length n is divided into parts of integer length. What is the maximum number of distinct lengths? It turns out that there are at most O(√n) distinct lengths. To produce as many distinct lengths as possible, include 1, 2, …, k. Since 1 + 2 + ⋯ + k = k(k+1)/2, k can be at most O(√n). Next we will see how this observation helps when designing algorithms.

Knapsack with few distinct weights

Consider a knapsack problem with integer weights [w1, w2, …, wk] such that w1 + w2 + ⋯ + wk = n; we must determine all possible weight sums. A standard knapsack algorithm solves this in O(nk) time, so if k = O(n), the time becomes O(n2). Since there are at most O(√n) distinct weights, we can do better by processing all weights of a certain value together.

For example, with weights [3, 3, 4], we process the two 3s and then the 4. The standard algorithm is easily modified so that each group of equal weights takes O(n) time, which yields an O(n√n) algorithm.

String construction

As another example, suppose we are given a string of length n and a dictionary of words with total length m. We must count the ways to construct the string using the words. Using dynamic programming, we calculate for each k = 0, 1, …, n the number of ways to construct the prefix of length k. One way is a trie containing the reverses of all words, which gives an O(n2 + m) algorithm. Another uses string hashing and the fact that there are at most O(√m) distinct word lengths, so we can restrict ourselves to lengths that exist. A set of all word hash values gives an O(n√m + m) algorithm.

15.1.4

Mo’s Algorithm

Mo’s algorithm processes range queries on a static array, whose values do not change between queries. Each query asks for something based on the values in a range [a, b]. Since the array is static, the queries can be processed in any order, and the trick is to use an order that keeps the work small. The algorithm maintains an active range, whose answer is known at each moment, and processes the queries one by one, moving the endpoints by inserting and removing elements.

The array is divided into blocks of k = O(√n) elements, and a query [a1, b1] is always processed before a query [a2, b2] if ⌊a1/k⌋ < ⌊a2/k⌋ or ⌊a1/k⌋ = ⌊a2/k⌋ and b1 < b2. Thus, all queries whose left endpoints fall in a block are processed one after another, sorted by their right endpoints. In this order the algorithm performs only O(n√n) operations: the left endpoint moves O(n) times O(√n) steps, and the right endpoint O(√n) times O(n) steps.

Consider a problem where we are given a set of ranges and asked to count the distinct values in each. We maintain an array count, where count[x] is the number of times x occurs in the active range. After adding x, we increase count[x] by 1; if it becomes 1, we increase the answer by 1. After removing x, we decrease count[x] by 1; if it becomes 0, we decrease the answer by 1. Each step takes O(1) time, so the algorithm works in O(n√n) time.

Why the ordering helps

Thus, both endpoints move a total of O(n√n) steps during the algorithm.

Mo’s algorithm is named after Mo Tao, a Chinese competitive programmer.[5]

15.2

Segment Trees Revisited

Until now the segment tree has been walked from the bottom up. The advanced variants are easier to write from the top down.

A segment tree is a versatile data structure that solves a large number of problems. So far we have seen only a small part of its possibilities. Now we discuss more advanced variants that solve more advanced problems.

Until now, we have implemented segment tree operations by walking from bottom to top. For example, we used the following function to calculate the sum in a range [a, b]:

a += n; b += n;
while (a <= b) { … a /= 2; b /= 2; }

The parameter k indicates the current position in tree. Initially k equals 1, because we begin at the root. The range [x, y] corresponds to k and is initially [0, n−1]. When calculating the sum, if [x, y] is outside [a, b], the sum is 0; if it is completely inside, the sum is found in tree. If it is partially inside, the search continues recursively into the left and right halves of [x, y].

In this implementation too, operations take O(log n) time, because the number of visited nodes is O(log n).

15.2.1

Lazy Propagation

Using lazy propagation, we can build a segment tree that supports range updates and range queries in O(log n) time. Updates and queries run from top to bottom, and updates are performed lazily, propagated down only when necessary. The nodes contain two types of information. As in an ordinary segment tree, each node holds the sum, minimum, or some other value for its subarray. In addition, a node may hold a lazy update not yet propagated to its children.

Consider a segment tree supporting two operations: increasing each value in [a, b] by a constant and calculating the sum in [a, b]. Each node has two values s/z: s is the sum of the range, and z is a lazy update meaning that all values in the range should be increased by z.

To increase the values in [a, b] by u, we modify the nodes as follows. If the range [x, y] of a node is completely inside [a, b], we increase its z value by u and stop. If [x, y] only partially belongs to [a, b], we continue recursively and afterwards calculate the node’s new s value. In both updates and queries, lazy updates are propagated downwards as we move. Before accessing a node, we check for an ongoing lazy update; if there is one, we update its s value, propagate it to its children, and clear its z value.

15.2.2

Dynamic Trees

An ordinary segment tree is static: each node has a fixed position in the tree array, and the structure requires a fixed amount of memory. In a dynamic segment tree, memory is allocated only for nodes actually accessed during the algorithm, which can save a large amount.

The nodes can be represented as structs, where value is the node’s value, [x, y] its range, and left and right point to the subtrees. A sparse segment tree initially has one node [0, n−1] with value zero, so every array value is zero. Updates add new nodes dynamically. Any root-to-leaf path contains O(log n) nodes, so each operation adds at most O(log n) nodes; after k operations the tree contains O(k log n) nodes. If all updated elements are known beforehand, a dynamic tree is unnecessary, because an ordinary tree with index compression works. That is not possible when the indices are generated during the algorithm.

A dynamic implementation also allows a persistent segment tree that stores the modification history. We can then access all versions of the tree that have existed. After each update most nodes remain the same, so each historical tree can be represented as new nodes plus subtrees of previous trees. Since each operation adds only O(log n) new nodes, the full history fits in memory.

15.2.3

Data Structures in Nodes

Instead of single values, nodes can contain data structures that maintain information about their ranges. For example, suppose we want to count the occurrences of an element x in a range [a, b]. Each node can hold a structure that answers how many times x appears in its range. The answer to a query is then assembled from the results of the nodes covering the range.

The remaining task is to choose the structure. A good choice is a map whose keys are array elements and whose values count occurrences in a range. Each query works in O(log2 n) time, because each node’s map takes O(log n) time. The tree uses O(n log n) memory: O(log n) levels, each holding n elements distributed among the maps.

15.2.4

Two-Dimensional Trees

A two-dimensional segment tree processes queries about rectangular subarrays. We build a segment tree over the columns, then give each node a segment tree over the rows. Queries take O(log2 n) time: O(log n) nodes of the main tree are accessed, and each takes O(log n) time.

The structure uses O(n2) memory: the main tree has O(n) nodes, each with a tree of O(n) nodes.

15.3

Treaps

A treap stores an array as a binary tree whose inorder walk is the array and whose weights form a heap.

A treap is a binary tree that stores an array so that we can efficiently split it into two arrays and merge two arrays into one. Each node has a weight and a value. A node’s weight is no larger than its children’s weights, and the node lies after all nodes in its left subtree and before all nodes in its right subtree.

The root has weight 1 and value D. Since its left subtree contains three nodes, the array element at position 3 has value D. A new node is assigned a random weight, which guarantees that the tree is balanced (height O(log n)) with high probability, so its operations stay efficient.

15.3.1

Splitting and Merging

Splitting creates two treaps that divide the array so that the first k elements go to the first treap and the rest to the second. We create two empty treaps and traverse the original from the root. At each step, if the current node belongs to the left treap, the node and its left subtree are added there and we recurse on its right subtree. Similarly, if it belongs to the right treap, the node and its right subtree go there and we recurse on its left subtree. Since the height is O(log n), the operation works in O(log n) time.

Merging creates one treap that concatenates the arrays. The two treaps are processed together, and at each step the root with the smallest weight is chosen. If that is the left root, the root and its left subtree move to the new treap, and its right subtree becomes the new root of the left treap. Similarly, if it is the right root, the root and its right subtree move, and its left subtree becomes the new root of the right treap. Since the height is O(log n), merging works in O(log n) time.

For example, split the example array so that the first array holds the first five elements. Node D belongs to the left treap, so D and its left subtree go left. Node C belongs to the right treap, so C and its right subtree go right. Then W goes left and I goes right. We may now swap the two arrays and concatenate them again.

The function split recursively splits the treap into left and right, so that left contains the first k nodes and right the rest. The function merge implements merging.

15.3.3

Additional Techniques

Splitting and merging are powerful, because they let us “cut and paste” arrays in logarithmic time. Treaps can also be extended to work almost like segment trees: for example, in addition to the size of each subtree, we can also maintain the sum of its values, the minimum, and so on.

One special trick related to treaps is that we can efficiently reverse an array by swapping the left and right child of each node. To do this efficiently, we introduce a field indicating whether the subtree should be reversed, and process the swaps lazily.

15.4

Dynamic Programming Optimization

The hard part of a dynamic program is often not the state — it is the transition that tries every previous state.

This section discusses techniques for optimizing dynamic programming. First, we focus on the convex hull trick, which finds minimum values of linear functions efficiently. After that, we discuss two other techniques based on properties of cost functions.

15.4.1

Convex Hull Trick

The convex hull trick finds the minimum value at a point x among n linear functions f(x) = ax + b. The idea is to divide the x-axis into ranges where one function is minimal. Each function has at most one range, and the ranges fit in a sorted list of at most n entries. With that list, the minimum at x is found in O(log n) time by binary search, so k queries take O(k log n). If the queries come in increasing order, we can process them in O(k) time by walking the ranges from left to right.

For example, take f1(x) = x + 2, f2(x) = x/3 + 4, f3(x) = x/6 + 5, and f4(x) = −x/4 + 7. At x = 4 the minimum is f2(4) = 16/3. First, f1 has the minimum value, then f2 has the minimum value, and finally f4 has the minimum value. Note that f3 is never minimal.

15.4.2

Divide and Conquer Optimization

The divide and conquer optimization applies to dynamic programming problems where a sequence s1, s2, …, sn must be divided into k subsequences of consecutive elements. A cost function cost(a, b) gives the cost of the subsequence sa, sa+1, …, sb. The total cost is the sum of the individual costs, and we want the division that minimizes it. Define solve(i, j) as the minimum cost of dividing the first i elements into j subsequences. To calculate solve(i, j), we find a position 1 ≤ p ≤ i that minimizes

solve(i, j) = min1 ≤ p ≤ i [ solve(p − 1, j − 1) + cost(p, i) ].

Checking all positions 1, 2, …, i takes O(n) time. Calculating every solve(i, j) this way gives an O(n2k) algorithm. The divide and conquer optimization improves this to O(nk log n), provided the cost function satisfies the quadrangle inequality

cost(a, c) + cost(b, d) ≤ cost(a, d) + cost(b, c)   for a ≤ b ≤ c ≤ d,

Let pos(i, j) be the smallest position p that minimizes the cost for solve(i, j). If the inequality holds, then pos(i, j) ≤ pos(i+1, j) for all i and j. Define calc(j, a, b, x, y) to calculate all solve(i, j) for a ≤ i ≤ b and a fixed j, knowing that x ≤ pos(i, j) ≤ y. It first calculates solve(z, j) with z = ⌊(a+b)/2⌋, then recurses into calc(j, a, z−1, x, p) and calc(j, z+1, b, p, y), where p = pos(z, j). To get all solve(i, j), call calc(j, 1, n, 1, n) for each j = 1, 2, …, k. Each call takes O(n log n) time, so the algorithm works in O(nk log n) time.

15.4.3

Knuth’s Optimization

Knuth’s optimization applies to dynamic programming problems where a sequence s1, s2, …, sn is divided into single elements by splitting operations. A cost function cost(a, b) gives the cost of processing sa, sa+1, …, sb, and we want to minimize the total splitting cost. Define solve(i, j) as the minimum cost of dividing si, si+1, …, sj into single elements; then solve(1, n) is the answer. To determine solve(i, j), find a position i ≤ p < j that minimizes

solve(i, j) = cost(i, j) + mini ≤ p < j [ solve(i, p) + solve(p + 1, j) ].

Checking all positions between i and j gives an O(n3) algorithm. Knuth’s optimization calculates the values in O(n2) time. It applies if cost(b, c) ≤ cost(a, d) and cost(a, c) + cost(b, d) ≤ cost(a, d) + cost(b, c) for all a ≤ b ≤ c ≤ d. Let pos(i, j) be the smallest position p that minimizes the cost for solve(i, j). If the inequalities hold, pos(i, j−1) ≤ pos(i, j) ≤ pos(i+1, j). Now perform n rounds 1, 2, …, n, and on round k calculate solve(i, j) where j−i+1 = k: the subsequences in increasing order of length. Since pos(i, j) lies between pos(i, j−1) and pos(i+1, j), each round takes O(n) time, and the total complexity is O(n2).

15.5

Miscellaneous

Four techniques that do not share a theme, except that each one rearranges a problem until an ordinary tool fits.

15.5.1

Meet in the Middle

The meet in the middle technique divides the search space into two parts of about equal size, performs a separate search for both of the parts, and finally combines the results of the searches. Meet in the middle allows us to speed up certain O(2n) time algorithms so that they work in only O(2n/2) time. Using an O(2n) algorithm we can process inputs where n ≈ 20, but using an O(2n/2) algorithm the bound is n ≈ 40.

Suppose that we are given a set of n integers and our task is to determine whether the set has a subset with sum x. We can easily solve the problem in O(2n) time by going through every possible subset, but next we will solve the problem more efficiently in O(2n/2) time using meet in the middle. The idea is to divide our set into two sets A and B such that both sets contain about half of the numbers. The first search generates all subsets of A and stores their sums to a list SA, and the second search creates a similar list SB for B. After this, it suffices to check if we can choose one element from SA and another element from SB such that their sum is x. With a good implementation, we can create the lists in O(2n/2) time in such a way that the lists are sorted. After this, we can use a two pointers algorithm to check in O(2n/2) time if the sum x can be created from SA and SB. Thus, the total time complexity of the algorithm is O(2n/2).

15.5.2

Counting Subsets

Let X = {0…n−1}, and each subset S ⊂ X is assigned an integer value[S]. Our task is to calculate for each S the sum of values of subsets of S. Next we will see how to solve the problem in O(2nn) time using dynamic programming and bit operations. The idea is to consider subproblems where it is limited which elements may be removed from S. Let partial(S, k) denote the sum of values of subsets of S with the restriction that only elements 0…k may be removed from S. Note that we can calculate any value of sum(S) using partial, because sum(S) = partial(S, n−1). To use dynamic programming, we have to find a recurrence for partial. First, the base cases are partial(S, −1) = value[S], because no elements can be removed from S. Then, in the general case we can calculate the values as follows:

partial(S, k) = partial(S, k − 1), if k ∉ S;
partial(S, k) = partial(S, k − 1) + partial(S \ {k}, k − 1), if k ∈ S.

Here we focus on the element k. If k ∈ S, there are two options: we can either keep k in the subset or remove it from the subset. There is a particularly clever way to implement the solution using bit operations. Namely we can declare an array that will contain the sum of each subset, initialize it with the values, and fill it with two nested loops. This code calculates the values of partial(S, k) for k = 0…n−1 to the array sum. Since partial(S, k) is always based on partial(S, k−1), we can reuse the array sum, which yields a very efficient implementation.

15.5.3

Parallel Binary Search

Parallel binary search is a technique that allows us to make some binary search based algorithms more efficient. The general idea is to perform several binary searches simultaneously, instead of doing the searches separately.

As an example, consider the following problem: There are n cities numbered 1, 2, …, n. Initially there are no roads between the cities. Then, during m days, each day a new road is built between two cities. Finally, we are given k queries of the form (a, b), and our task is to determine for each query the earliest moment when cities a and b are connected. We can assume that all requested pairs of cities are connected after m days.

Let us first consider an easier problem where we have only one query (a, b). In this case, we can use a union-find structure to simulate the process of adding roads to the network. After each new road, we check if cities a and b are connected and stop the search if they are. Both adding a road and checking if cities are connected take O(log n) time, so the algorithm works in O(m log n) time.

How could we generalize this solution to k queries? Of course we could process each query separately, but such an algorithm would take O(km log n) time, which would be slow if both k and m are large. The idea is to assign each query a range [x, y] which means that the cities are connected for the first time no earlier than after x days and no later than after y days. Initially, each range is [1, m]. Then, we simulate log m times the process of adding all roads to the network using a union-find structure. For each query, we check at moment u = ⌊(x+y)/2⌋ if the cities are connected. If they are, the new range becomes [x, u], and otherwise the range becomes [u+1, y]. After log m rounds, each range only contains a single moment which is the answer to the query.

During each round, we add m roads to the network in O(m log n) time and check whether k pairs of cities are connected in O(k log n) time. Thus, since there are log m rounds, the resulting algorithm works in O((m+k) log n log m) time.

15.5.4

Dynamic Connectivity

Suppose that there is a graph of n nodes and m edges. Then, we are given q queries, each of which is either “add an edge between nodes a and b” or “remove the edge between nodes a and b.” Our task is to efficiently report the number of connected components in the graph after each query. If edges would only be added to the graph, the problem would be easy to solve using a union-find data structure, but the removal operations make the problem much more difficult. Next we will discuss a divide and conquer algorithm for solving the offline version of the problem where all queries are known beforehand, and we are allowed to report the results in any order.

The idea is to create a timeline where each edge is represented by an interval that shows the insertion and removal time of the edge. The timeline spans a range [0, q+1], and an edge that is added on step a and removed on step b is represented by an interval [a, b]. If an edge belongs to the initial graph, a = 0, and if an edge is never removed, b = q+1.

To process the intervals, we create a graph that has n nodes and no edges, and use a recursive function that is called with range [0, q+1]. First, if [a, b] is completely inside the interval of an edge, and the edge does not belong to the graph, it is added to the graph. Then, if the size of [a, b] is 1, we report the number of connected components, and otherwise we recursively process ranges [a, k] and [k, b] where k = ⌊(a+b)/2⌋. Finally, we remove all edges that were added at the beginning of processing the range [a, b]. Always when an edge is added or removed, we also update the number of components. This can be done using a union-find data structure, because we always remove the edge that was added last. Thus, it suffices to implement an undo operation for the union-find structure, which is possible by storing information about operations in a stack. Since each edge is added and removed at most O(log q) times and each operation works in O(log n) time, the total running time of the algorithm is O((m+q) log q log n).
